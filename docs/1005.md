# 会话压缩摘要 · ScreenSpy

## 一、项目定位
Windows 11 后台小工具：统计**真实活跃使用时长**（去挂机/锁屏/睡眠），**按软件分别统计**，以**半透明极简卡片贴在桌面**展示，含**每日总限额 + 单软件限额** Toast 提醒（80%/100%，去重一次）。个人自用，纯提醒不锁屏。**不做多显示器。**

## 二、环境（实测）
Windows 11 **26H2 / build 26300.9457**、**`.NET 10.0.12`**、`net10.0-windows`、1920×1200 @125%、VS 2026。
工程：`D:\project\ScreenSpy\`，`ScreenSpy.slnx` + **单一 WPF 产品工程 `ScreenSpy/`**（扁平结构，**不建子项目**是既定决策）。主界面**已定稿 WPF**。

> 🔄 **2026-10-06 追加：活跃口径统一 + 修复“重启后今日变小”**
> 原实现里只有“已归因软件”会落库，而“桌面/外壳/自身”与“无前台/未知”**只存内存**，
> 于是**重启续算后“今日真实活跃”会凭空变小**（不报错、只是数字变小 —— 正是本项目最忌讳的那类缺陷）。
> 现改为：锁屏/登录界面**完全不计入**（单列“锁屏剔除”，守恒等式扩为四项）；
> 桌面/外壳/自身 → **「不计入使用时长」**；无前台/未知 → **「无前台/未知」**；
> 两者**都计入今日**，并**一并落库**（新表 `daily_activity`，schema 1→2）与启动续算；
 > 主面板与卡片都会标出这两栏。M3 自检 77→80 项、M4 30→36 项、M6 36→41→51→52 项（含 D 组：主界面榜单「不计入统计」行，**占比列留空**）、**M7 新增 78 项**（第二轮补 D 组：调整入口互斥）。

## 四、M0 核心结论（最重要，含客观证据）

**路线 A（`SetParent` 嵌进 `WorkerW`/`Progman`）失败，且是"假阳性"式失败**：所有 API 全绿（`SetParent` 成功、`GA_ROOT==Progman`、`IsWindowVisible=true`、`UpdateLayeredWindow` 返回 true），**但窗口从未上屏**。

- **坐实手段**：7 个纯色探针 + 截屏像素判定 → 只有**顶层对照探针**可见，全部子窗口探针 **0 像素**。
- **根因**：`Progman` 含 **`WS_EX_NOREDIRECTIONBITMAP`**，由 **DirectComposition** 呈现；**第三方子 HWND 不在其合成树内 → 永不上屏**。（`DWMWA_CLOAKED` 全 0，说明不是遮盖机制。）
- **翻案**：读 **Rainmeter 源码**发现它**根本不用 `SetParent`**（0 次调用），而是**顶层窗口 + `HWND_BOTTOM` + z 序自锁 + 显示桌面检测/复位**。→ **放弃 A/C，改 B+**。
- **附带**：26H2 上 `SHELLDLL_DefView` 直接是 `Progman` 子窗口；壁纸层是 `Progman` 的全屏子 `WorkerW`；**不存在**旧文档 §5.8 说的"顶层同级 `WorkerW`"（顶层 17 个 `WorkerW` 全是 170×47 无关窗口）。另外 `0x052C` 仍有效，但应"先查找、找不到才注入"。

**路线 B+ 已实测通过**（你要的三点全达成）：在桌面 ✅ / 被其它窗口覆盖 ✅ / **Win+D 不最小化 ✅**（`IsIconic=False`；机理是"桌面被抬起时把卡片复位到其上"，**不是阻止最小化**）。另有鼠标穿透、任务栏/Alt+Tab 隐藏、无残影，均客观判定通过。

## 六、五条核心方法论（跨阶段复用）
1. **API 全绿 ≠ 像素上屏**——判据必须落到像素/命中测试；
2. **不要嵌入桌面树**（26H2 是 DComp 呈现）；
3. **Win+D 免疫靠 z 序复位，不是阻止最小化**；
4. **不要用"读源码推断"替代"实测"**（判据极性就错在这）；
5. **本机测不出的 bug 靠"换环境会怎样"发现**（会话号=1）；另：**"保留原始"与"聚合展示"必须分两层存**。
