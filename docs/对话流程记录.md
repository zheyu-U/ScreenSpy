# 会话压缩摘要（ScreenSpy 项目）

## 三、M0 关键结论（已验证，含客观证据）

**决策链**：先试"真嵌入"（路线 A）→ **失败** → 求证 Rainmeter 源码 → **放弃嵌入，改为路线 B+**。

### 路线 A 失败（真嵌入 WorkerW/Progman 子窗口）
- 表现：窗口**从未上屏**，但所有 API 全绿（`SetParent` 成功、`GA_ROOT==Progman`、`IsWindowVisible=true`、`UpdateLayeredWindow` 返回 true）——**假阳性**。
- 证据：7 个纯色探针 + 截屏像素判定 → 唯一可见的是**顶层对照探针 P0**；所有子窗口探针 0 像素（分层/不透明、WorkerW/Progman 各种组合皆然）。
- 根因：`Progman` 扩展样式含 **`WS_EX_NOREDIRECTIONBITMAP`**，由 **DirectComposition** 呈现；**第三方子 HWND 不在其合成树内 → 永不上屏**。`DWMWA_CLOAKED` 全为 0（不是遮盖）。
- 附带：26H2 上 `SHELLDLL_DefView` **直接是 `Progman` 子窗口**；壁纸层是 `Progman` 的全屏子 `WorkerW`；**不存在**文档 §5.8 说的顶层同级 `WorkerW`（顶层 17 个 `WorkerW` 全是 170×47 无关窗口）。

### Rainmeter 求证（决定性）
**Rainmeter 根本不用 `SetParent`（0 次调用）**，它就是**顶层窗口 + `HWND_BOTTOM` + z 序自锁 + 显示桌面检测/复位**。凭此扛住 Win+D —— **不是阻止最小化，而是发现桌面被抬起就把自己插回桌面之上。**

### 路线 B+ 最终方案（已实测通过）
| 机制 | 落地 |
|---|---|
| z 序自锁 | `WM_WINDOWPOSCHANGING` → `flags \|= SWP_NOZORDER` |
| 隐藏探针窗口 | 用于 z 序探测（`HWND_BOTTOM`，不建表面） |
| 显示桌面检测 | **`显示桌面 ⟺ HostZ < ProbeZ`**（桌面宿主跑到探针之前） |
| 复位 | 正常→`HWND_BOTTOM`；显示桌面→`TOPMOST` 后 `NOTOPMOST`（插到 topmost 带之下） |
| 事件加速 | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` |
| 采样密度 | 250ms ⇄ 显示桌面期间 100ms |
| 窗口样式 | `WS_POPUP` + `WS_EX_LAYERED\|TRANSPARENT\|NOACTIVATE\|TOOLWINDOW` |

**验证结果（两轮一致）**：S1 正常 576px → **S2 Win+D 仍 576px（`IsIconic=False`，HostZ 161→15）** → S3 还原一致 → S4 被覆盖 0px → S5 恢复 576px。**三项需求全部达成**：在桌面 ✅、会被窗口覆盖 ✅、Win+D 不最小化 ✅（另有鼠标穿透、任务栏/Alt+Tab 隐藏、无残影，均客观判定通过）。

## 四、可复用教训（9 条，重点 4）
1. **API 全绿 ≠ 像素上屏**——判据必须落到像素/命中测试。
2. **不要嵌入桌面树**（26H2 是 DComp 呈现，第三方子窗口不上屏）。
3. **Win+D 免疫的正解是 z 序复位，而非阻止最小化**。
4. **不要用"读源码推断"替代"实测"**——照抄的判据极性是错的，靠实测纠正。
5. 判定嵌入**不能用 `GetParent`**（带 `WS_POPUP` 时返回 owner）→ 用 `GetAncestor`。
6. `SetParent` 不会自动把 `WS_POPUP` 改 `WS_CHILD`。
7. `WindowFromPoint` 不可靠（否决）。
8. 像素判定必须先校验"桌面是否可见"（首次截屏被 VS 遮挡，结论无效）。
9. 26H2 `0x052C` 仍有效但**先查找、找不到才注入**；注入会新增壁纸 `WorkerW`，注销/重启 Explorer 回收。

## 三、当日最关键的几个认识

1. **API 全绿 ≠ 像素上屏。** 路线 A 的自动检测“全绿”，屏幕上却什么都没有；引入截屏像素判定后才定性为**假阳性**。此后本项目所有“是否真的显示了”都只认像素。
2. **不要嵌入桌面树。** 26H2 上 `Progman` 带 `WS_EX_NOREDIRECTIONBITMAP`（DirectComposition），第三方 `SetParent` 进去的子窗口不上屏；Rainmeter 这类成熟工具也**从不嵌入**。
3. **Win+D 免疫的正确解法是 z 序复位。** 卡片并未被最小化（`IsIconic` 始终 False），只是被抬起的桌面**盖住**；检测到“显示桌面”就把卡片插回桌面之上即可。
4. **（M1）自检的“前提”本身可能掩盖缺陷。** 调度器 bug（`Ticked?.Invoke(ProcessHeartbeat())` 在**无人订阅事件**时实参根本不求值 → 心跳完全不执行）之所以躲过自检，只因自检**恰好订阅了事件**；回归用例必须刻意覆盖退化配置（无订阅者）。
5. **（M2）结构体布局不能靠文档推断，还要问“换个环境会怎样”。** `WTSINFOEX.SessionId` 实测在偏移 **8**（`Level` 后有 4 字节填充），硬编码偏移会静默读错；更隐蔽的是「会话号为 1」时错位命中的「伪头部」恰好**看起来完全合法**——本机（会话号 2）**永远测不出来**，只能靠对抗性构造用例发现。
6. **（M4）事件顺序会决定“能不能拿到数据”。** 调度器跨天时**先** `DayRolled`（榜单被清空）**后** `Ticked`，而 C# 事件按**订阅顺序**调用 —— 于是“到点去读一眼内存榜单再写库”这种看似自然的写法，会在午夜**永久丢掉昨天的尾段**。凡是要持久化的订阅者，都应**自己按拍携带的日期累加**，不依赖别人的内存状态。

7. **（M5a）“能启动”与“看得见在启动”是两件事。** 把采集链路接进产品启动流程之后，如果界面仍是空白模板，就只能靠翻库文件去确认到底有没有生效；把状态做成**可见面板**，才让“接线是否成功”从“需要考古”变成**一秒内可判断**。

8. **（M5b）不要用语义模糊的便捷属性去判定状态。** `Process.MainWindowHandle` 在同一次运行里先报 0、后报非零（它会挑“当前可见的顶层窗口”）；改成 `EnumWindows` 直接列出全部顶层窗口后，结果 2/2 稳定。

9. **（M6）派生值不能是“等着别人来填”的字段。** `TodayTotal` 第一版由组合根赋值，自检立刻发现**手工构造的快照会得到 `0:00`**；改成**计算属性**后，从结构上消除了“漏填且不报错”。同理，**对外展示口径与守恒口径必须分开命名**（`TodayTotal` vs `TodayActive`），否则改一处会同时破坏界面与恒等式。
