# 核心接口说明（给 UI 开发者）

> **本文是写给"重写 UI 的人"的接口面清单。**
> 配套阅读：`UI-重写思路.md`（为什么这么分层）与 `未来计划.md`（什么时候做什么）。

---

## 零、先回答一个常见问题

> **"写 UI 要调用很多数据接口，这些接口是不是要等拆工程之后才能得到？"**

**不是。接口面今天就已经存在（而且已经在被主界面使用）。**

| 说法 | 事实 |
|---|---|
| "要等拆工程才有接口" | ❌ 错的。`ProductRuntime` 的公开成员**就是**接口面，主界面今天就在调它 |
| 拆工程带来什么 | 把这份**隐式**接口面变成**显式契约**（`IScreenSpyCore`），并让**编译器**阻止"核心误引用 UI" |
| 那 M14 契约抽取做什么 | 把**散落在 `MainWindow` 上的纯函数与注入委托**收进契约。这与"拆不拆工程"**无关** |
| 那 M15 进程化做什么 | 只是把"同进程直调"换成"管道调用"。**UI 代码不用改**（因为它是针对接口写的） |

**一句话**：
> **接口今天就有；M14 把它显式化（为了把验证网从 UI 里解出来）；M15 只是换一个实现（为了内存）。**

## 一、总览：UI 与核心的三种交互

```
                     ┌─────────────── 核心（ProductRuntime + 组件）───────────────┐
读（每秒/按需）  ←── │  Snapshot() / AppsToday() / LimitStatuses() / ReadChart()   │
                     │  Categories / Aliases / Limits / LimitThresholdsText / …    │
命令（稀疏）     ──→ │  SetLimit / RenameApp / MergeApps / SetAppCategory / …      │
推送（事件）     ←── │  event LimitNotified                                        │
                     └──────────────────────────────────────────────────────────────┘
```

**核心交互原则（已写在代码注释里，请遵守）**：
1. **读走"厚快照"**：`Snapshot()` 是一份**只读 DTO**，在 UI 线程调用是安全的，且**永不抛异常**；
2. **写走"细命令"**：每个命令都**返回结果**（`bool` / `out bool removed` / 结果枚举），
   **失败必须如实返回 false，不许假装成功**；
3. **推送必须 marshal**：`LimitNotified` 可能在**心跳线程**上触发，UI 必须自行切回 UI 线程。

## 二、当前真实接口面（三组）

### A 组：`ProductRuntime` 的公开成员（主界面/托盘已经在用）

| 用途 | 成员 | 备注 |
|---|---|---|
| **状态快照** | `RuntimeStatus Snapshot()` | 每秒调用；永不抛 |
| **今日软件** | `IReadOnlyList<AppUsageEntry> AppsToday()` | 按今日时长降序，**含库中基线**；「软件与分类」一节用 |
| **身份：分类** | `IReadOnlyList<string> Categories` | 当前分类列表 |
| | `string CategoryOf(string appKey)` | 未分类返回**空串** |
| | `bool SetAppCategory(string appKey, string category)` | 空串 = 取消分类 |
| | `bool CreateCategory(string name)` | |
| | `bool DeleteCategory(string name, out bool removed)` | `removed` 用于给出**准确**反馈 |
| **身份：合并** | `IReadOnlyDictionary<string, string> Aliases` | 原始键 → 归一键 |
| | `bool MergeApps(string fromKey, string toKey)` | |
| | `bool UnmergeApp(string rawKey, out bool removed)` | 仅对今后生效 |
| **身份：命名** | `string DefaultDisplayName(string appKey)` | 系统默认名（友好名表或归一键本身） |
| | `string DescribeApp(string appKey)` | 给用户看的显示名（用于"跟谁重名了"） |
| | `string? ValidateRename(string appKey, string displayName)` | 返回 null = 合法；否则为**可读原因** |
| | `AppRenameResult RenameApp(string appKey, string displayName, out string conflictAppKey)` | 结果：成功 / 冲突 / 非法 / 存储不可用 |
| **限额** | `IReadOnlyList<LimitRule> Limits` | 当前规则（展示用） |
| | `IReadOnlyList<LimitStatus> LimitStatuses()` | 各条当前状态（**纯读取，无副作用**） |
| | `bool SetLimit(LimitKind kind, string target, TimeSpan limit)` | |
| | `bool RemoveLimit(LimitKind kind, string target, out bool removed)` | |
| | `string LimitThresholdsText` | 如 `"80,100"` |
| | `bool SetLimitThresholds(string? text, out string? error)` | 非法输入 → false + 原因，**不写库** |
| | `string? LimitError` | 限额内部错误（正常为 null） |
| **图表** | `IReadOnlyList<string> ChartCategories` | 「分类」维度的候选 |
| | `(IReadOnlyList<string> keys, string? error) ReadChartApps()` | 「软件」维度的候选（近 7 天出现过的） |
| | `ChartResult ReadChart(ChartScope scope, int days = 7)` | 失败时返回**可显示原因**，不是空图 |
| **卡片放置** | `WidgetPlacement LoadWidgetPlacement()` | 形态 + 坐标；含"屏幕外兜底" |
| | `void SaveWidgetPosition(int x, int y)` | 存储不可用则静默忽略 |
| | `void SaveWidgetMode(WidgetMode mode)` | |
| **诊断** | `IReadOnlyList<string> Warnings` | 降级说明（正常为空） |
| | `string DatabasePath` / `string LogDirectory` | |
| **生命周期** | `void Dispose()` | 停心跳 → 刷日志尾段与落库尾段 |
| **启动** | `static HostStartResult Start(StartupOptions)` | 单实例 + 降级；结果含 `Message` |

### B 组：`App` 注入到 `MainWindow` 的 6 个委托

这些**不在 `ProductRuntime` 上**，而是 `App` 在装配时注入（因为它们涉及卡片/注册表等核心之外的对象）。
**它们同样是接口面的一部分，未来应一并收进 `IScreenSpyCore`。**

| 属性 | 签名 | 用途 |
|---|---|---|
| `IsAdjusting` | `Func<bool>` | 卡片是否处于「调整位置」这个**临时**会话 |
| `ToggleAdjust` | `Action` | 进入/结束「调整位置」 |
| `IsFloating` | `Func<bool>` | 卡片**常态**是否浮动（**不是**当前形态！） |
| `ToggleCardMode` | `Action` | 切换卡片**常态**形态并持久化 |
| `QueryAutoStart` | `Func<AutoStartState>` | 开机自启的**真实注册表状态**（每秒回读） |
| `SetAutoStart` | `Action<bool>` | 写入/删除 Run 键 |

> ⚠️ **`IsFloating` 读的是常态、`IsAdjusting` 读的是临时会话** —— 这个区别是本项目栽过的坑
> （见 `M7-验证.md` §3.4）：读错会让"调整中"与"常态浮动"混为一谈，
> 进而**永久禁用**某个按钮、用户再也切不回嵌入。

**卡片可见性**（托盘菜单）：由 `TrayIconHost` 的 `isCardVisible` / `setCardVisible` 委托承担，
同样属于"UI 对核心的命令面"。

### C 组：事件

| 成员 | 签名 | 线程约束 |
|---|---|---|
| `LimitNotified` | `event Action<LimitNotification>?` | **可能在心跳线程触发 → UI 必须 marshal** |

## 三、契约类型清单（UI 会碰到的 DTO）

| 类型 | 用途 | 备注 |
|---|---|---|
| `RuntimeStatus` | 每秒快照 | **纯只读 DTO**；`TodayTotal` 等是计算属性 |
| `AppUsageEntry` | 一个软件的今日用量 | `MergeKey`（归一键）/ 显示名 / 时间 / 占比 |
| `LimitKind` / `LimitRule` / `LimitStatus` | 限额 | `LimitKind`：总 / 软件 / 分类 |
| `ChartScope` / `ChartResult` | 图表 | 维度（总量 / 软件 / 分类）+ 目标键 |
| `AppRenameResult` | 改名结果 | 成功 / 冲突 / 非法 / 存储不可用 |
| `WidgetPlacement` / `WidgetMode` | 卡片形态与坐标 | `WidgetMode`：`Embedded` / `Floating` |
| `AutoStartState` | 自启状态 | ⚠️ 现为 `internal`；跨进程前需提升为契约类型（含 `Available` / `Enabled` / `Command` / `Error`） |
| `LimitNotification` | 提醒载荷 | |

> **跨进程前的必要动作**：这些类型里凡是 `internal` 的（如 `AutoStartState`），
> 都要提升为 `Contracts` 工程里的**公开**类型 —— 否则 IPC 序列化会撞到可见性。

## 四、未来的 `IScreenSpyCore` 草案

> 下面是**设计草案**，用于 M14 契约抽取；成员与第二节一一对应，不引入新语义。

```csharp
public interface IScreenSpyCore
{
    // ---- 读：状态 ----
    RuntimeStatus Snapshot();

    // ---- 读：今日软件 ----
    IReadOnlyList<AppUsageEntry> AppsToday();

    // ---- 读：身份 ----
    IReadOnlyList<string> Categories { get; }
    string CategoryOf(string appKey);
    string DefaultDisplayName(string appKey);
    string DescribeApp(string appKey);
    IReadOnlyDictionary<string, string> Aliases { get; }

    // ---- 命令：身份 ----
    bool SetAppCategory(string appKey, string category);
    bool CreateCategory(string name);
    bool DeleteCategory(string name, out bool removed);
    bool MergeApps(string fromKey, string toKey);
    bool UnmergeApp(string rawKey, out bool removed);
    string? ValidateRename(string appKey, string displayName);
    AppRenameResult RenameApp(string appKey, string displayName, out string conflictAppKey);

    // ---- 读：限额 ----
    IReadOnlyList<LimitRule> Limits { get; }
    IReadOnlyList<LimitStatus> LimitStatuses();
    string LimitThresholdsText { get; }

    // ---- 命令：限额 ----
    bool SetLimit(LimitKind kind, string target, TimeSpan limit);
    bool RemoveLimit(LimitKind kind, string target, out bool removed);
    bool SetLimitThresholds(string? text, out string? error);

    // ---- 读：图表 ----
    IReadOnlyList<string> ChartCategories { get; }
    (IReadOnlyList<string> Keys, string? Error) ReadChartApps();
    ChartResult ReadChart(ChartScope scope, int days);

    // ---- 读/命令：卡片 ----
    WidgetPlacement LoadWidgetPlacement();
    void SaveWidgetPosition(int x, int y);
    void SaveWidgetMode(WidgetMode mode);
    bool IsAdjusting { get; }          // 现为 Func<bool> 委托
    void ToggleAdjust();               // 现为 Action 委托
    bool IsFloating { get; }           // 常态形态！现为 Func<bool> 委托
    void ToggleCardMode();             // 现为 Action 委托
    bool IsCardVisible { get; }
    void SetCardVisible(bool visible);

    // ---- 读/命令：自启 ----
    AutoStartState QueryAutoStart();   // 现为 Func<AutoStartState> 委托
    void SetAutoStart(bool enabled);   // 现为 Action<bool> 委托

    // ---- 诊断 ----
    IReadOnlyList<string> Warnings { get; }
    string DatabasePath { get; }
    string LogDirectory { get; }

    // ---- 推送 ----
    event Action<LimitNotification>? LimitNotified;
}
```

**`out` 参数与跨进程的冲突（M15 必须处理）**：
`DeleteCategory` / `UnmergeApp` / `RemoveLimit` / `RenameApp` / `SetLimitThresholds` 用了 `out` 参数 ——
**IPC 不能直接传 `out`**。两种处理：
1. 在 `Contracts` 里为每处定义**结果类型**（如 `RemoveLimitResult(bool Ok, bool Removed)`）——
   **推荐**，因为它同时也让"失败原因"可以随结果返回；
2. 或者由 `PipeCoreClient` 在客户端侧拼装（把远程返回值塞进 `out`）——
   实现简单但**结果类型仍然值得定义**（否则错误信息会丢失）。

> 建议在 **M14** 就把这些 `out` 参数改成**结果类型**，那时还在同进程、改动可有自检兜住；
> 等到 M15 再改，问题会和 IPC 混在一起。

## 五、设计规则（写 UI 时请遵守）

| 规则 | 原因 |
|---|---|
| **厚快照 + 细命令** | 快照一次拿全（几百字节）；不要"每个小问题发一次请求" |
| **纯函数在 UI 侧本地算** | `ValidateRename` / `DefaultDisplayName` / `DescribeApp` 这类纯函数，在拿到身份数据后可本地计算，不必往返 |
| **快照永不抛异常** | 展示层不该因为核心内部异常而崩 |
| **命令必须返回真实结果** | 失败就是失败，"假装成功"会产生"界面在骗人"这类不报错的错 |
| **不要在 UI 侧重新实现口径** | 图表聚合、身份解析、限额判定**只在核心**算；UI 侧再来一份 = 双份漂移 |
| **不要读数据库** | UI 直连 SQLite 会绕过核心的口径逻辑（同上一条） |
| **UI 线程只做展示** | 卡片在自己的 STA 线程；心跳在后台；`LimitNotified` 在心跳线程 |

## 六、线程与调用约束

| 调用 | 允许的线程 | 说明 |
|---|---|---|
| `Snapshot()` | **任意**（含 UI 线程） | 内部短暂持锁；返回平面拷贝 |
| `AppsToday()` / `LimitStatuses()` / `ReadChart()` | **UI 线程可以**（按需刷新） | 读库走**短连接**，与后台写线程不共享连接对象 |
| 命令（`Set*` / `*App` …） | **UI 线程**（用户动作触发） | 内部有锁与事务 |
| `LimitNotified` 回调 | **可能在心跳线程** | **必须自行 marshal 到 UI 线程** |
| 卡片 `ModelFactory` | **卡片自己的 STA 线程** | 每秒调 `Snapshot()` 取数 |

## 七、接口可用性时间线

| 阶段 | 接口形态 | UI 侧要做什么 |
|---|---|---|
| **今天** | `ProductRuntime` 公开成员 + `App` 注入的 6 个委托 | 无（现状） |
| **M14（契约抽取）** | 显式 `IScreenSpyCore`；纯函数/视图模型移出 `MainWindow` | **不必改**（同进程直调接口）；但**重写 UI 时请针对接口写** |
| **M15（进程化）** | `PipeCoreClient : IScreenSpyCore` | **仍不必改**；但需处理"核心未运行 / 已断开 / 版本不匹配"三种状态 |
| **M16（主界面重写）** | 不变 | 你主导；框架可自由选择 |

**给 UI 开发者的一句话**：
> 把 `IScreenSpyCore` 当成你的**唯一数据入口**。今天拿到的实现是同进程的 `ProductRuntime`，
> 将来会变成一个管道客户端 —— **你的代码不需要知道差别**。
