## 3. 装配顺序（顺序本身就是契约）

```
1. 单实例保护          ← 必须在打开数据库之前
2. ActivityScheduler   ← M1 计时核心（唯一“致命”依赖）
3. SessionPauseBridge  ← M2；构造时即做一次锁屏探测（启动初值）
4. AppUsageBridge      ← M3；旁听心跳
5. AppUsageStore       ← M4；旁听 Observed
   AppActivityLogger   ← 原始日志；同样旁听 Observed
6. 启动续算（Seed）     ← 必须在 Start() 之前：Seed 会重置当日状态
7. Start()             ← 开始心跳
```

**释放顺序与装配相反**：先 `Stop()`（不再产生观测）→ 刷日志尾段 → 刷落库尾段 → 其余 → 互斥体。

## 4. 降级策略（本次确认：降级继续 + 显示警告）

| 故障 | 行为 | 为什么这么选 |
|---|---|---|
| **SQLite 打不开**（被占用/损坏/磁盘满） | 计时与界面照常，仅**不落库、不续算**；调用 `ClearPools()` 清理半开连接 | 存储坏了不该让计时器也停 |
| **日志目录不可写** | **启动时就探测**（建目录 + 写删临时文件）→ 跳过日志并警告 | `ActivityLogWriter` 是懒建目录的，否则失败会推迟到“第一次写盘”，很容易被忽略成“日志有点慢” |
| **会话监听初始化失败** | 继续运行，但明确警告“锁屏/睡眠**可能被计入**” | 少一层保护比不能启动好，但必须让人知道 |
| **空闲源不可用** | 警告“无法判定挂机，时长会偏大” | 同上 |
| **单实例保护不可用**（权限等） | **放行运行**并警告 | 保护失效不该等于“程序打不开” |
| 计时核心建立失败 | **启动失败**（弹窗 + 退出码 1） | 这是唯一的致命依赖，没有它就没有意义 |

所有降级都会变成主界面上的一条**可见文字**，而不是被吞掉。

## 6. 已知局限（如实声明）

1. **关闭窗口即退出**。托盘属 M5，届时才改为“关闭不退出”。在此之前请勿把它当作常驻程序使用。
2. **单实例提示是模态对话框**，需手动关闭。日后做自启（M12）时需重新评估：无人值守场景下弹窗并不合适。
3. **续算只覆盖当天**（与 M4 一致）；历史日期仅供 M10 的 7 天图使用。
4. **状态面板不是最终界面**：不做设置、不做 7 天图、不做限额编辑（M8/M9/M10）。
5. **产品库现在真实存在**：`%LOCALAPPDATA%\ScreenSpy\data.db` 已由验证过程创建（含本次验证期间的少量数据）。
6. **`--data-dir` 等开关是开发期工具**，未在界面中暴露；拼错会退回默认路径（因此加了“未知参数”警告）。
7. 未做真正的“随机启动 + 长时间常驻”观察（属 M12 验收）。
