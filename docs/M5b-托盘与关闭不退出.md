## 3. 关键设计：用户暂停必须与 M2 的锁屏暂停**分开**

这是本次唯一容易埋雷的地方，值得单独说明。

**问题**：M2 的 `SessionPauseBridge` 每 5 秒用会话状态**重写** `ActivityScheduler.Paused`。若托盘的「暂停统计」也写同一个字段，用户刚点的暂停会在**几秒后被静默清除** —— 表现为「点了暂停，但过一会儿又开始计时」，且没有任何报错。

**方案**：两个独立的 `volatile` 标志位，生效暂停取**或**：

```
IsPaused = Paused（锁屏/睡眠，M2 写）|| UserPaused（用户手动，托盘写）
```

**语义（D33 确认）**：暂停期间**只不计时**；心跳、前台采样、原始日志照常运行。因此日志里会出现 `reason=paused` 的段落 —— 这正好回答了「这段时间为什么没算」。

**回归保护**：`M1SelfCheck` 新增 4 项（6a–6d），其中 6b 专门模拟「M2 探测把 `Paused` 写回 false」后用户暂停**必须仍然生效**。

### 5.7 一个方法学教训（与 M0 同源）

第一次量「关闭后主窗口」时，我先用 `Process.MainWindowHandle`，得到一个**自相矛盾**的结果：
同一次运行里前一分钟读到 `0`、后一分钟读到非零。原因是该属性会挑「当前可见的顶层窗口」，
桌面上一有瞬时窗口（tooltip 之类）它就可能换一个目标。

→ 改为 `EnumWindows` 直接列出该进程的全部顶层窗口（类名 / 可见性 / 标题），**2/2 次结果完全一致**。

> 教训：**不要用一个语义模糊的便捷属性去判定状态**；能直接刻画就直接刻画。

### 5.9 后续修正：「已暂停」显示口径缺陷（2026-10-06，事后复查发现并修复）

**性质**：**静默出错** —— 不报错、不崩溃，但**界面在骗人**。与 §3 的「用户暂停被静默清除」同源，
属《阶段总结》§8 点名的同类缺陷（与 `Ticked?.Invoke(ProcessHeartbeat())`、WTS 会话号、`limits.target=NULL` 并列）。

**症状**（**只在**用托盘「暂停统计」时出现）：

| 消费点 | 改前（错误） | 改后（正确） |
|---|---|---|
| 状态面板 `MainWindow.DescribeState` | 落进「未活跃」分支 → 显示 **「挂机中…」** | **「已暂停（托盘手动暂停）」** |
| 状态面板 `MainWindow.DescribeSession` | `暂停=否` | `暂停=是` |
| 托盘 tooltip `TrayIconHost.Refresh` | 无后缀 | **「ScreenSpy · 今日 h:mm:ss（已暂停）」** |

仅锁屏 / 睡眠时行为**不变**（仍显示「锁屏」「睡眠/休眠」）—— 因为 `IsPaused` 中 `Paused` 依旧成立，
两种来源的文案因此可以区分。

**根因**：`RuntimeStatus.Paused` 的注释写的是「**生效暂停**（锁屏/睡眠 或 用户手动，任一成立）」，
但组合根 `ProductRuntime.Snapshot()` 里写的是只含 M2 会话标志的那一半：

```csharp
status.Paused = scheduler.Paused;   // ← 只含 M2 的锁屏/睡眠标志，漏掉用户手动暂停
```

正确口径应是 `scheduler.IsPaused`（`= Paused || UserPaused`）。
这正是本项目反复强调的那类错误：**字段名与注释一致，代码却只填了一半**，编译与自检都不报错。

**修复**（`ScreenSpy/AppHost/ProductRuntime.cs`）：

```csharp
status.Paused = scheduler.IsPaused;        // 生效暂停 = 会话暂停 || 用户手动暂停
status.UserPaused = scheduler.UserPaused;  // 独立保留，供界面区分「为什么暂停」
```

**为什么 M5b 自检当时没咬住**：`M5SelfCheck` 原先只验**调度器字段**（M1 的 6a–6d 暂停来源回归）与
**菜单回调**，从未检验 `ProductRuntime.Snapshot()` 产出的 `RuntimeStatus` DTO。
缺陷恰在**组合根的赋值处** —— 在自检里自己 `new RuntimeStatus { … }` 永远测不到那一行。

**补强（自检 21 → 29 项）**：

1. **新增 D 组「组合根」5 项**：启动一个**真实的** `ProductRuntime`
   （`--no-store --no-raw-log --probe-ms=0`，因而无文件副作用、也无周期探测中途改写暂停位），
   走它真实的 `Snapshot()`：
   - 组合根启动成功（降级开关下）；
   - 初始（会话/用户均未暂停）→ `Paused=false`；
   - `UserPaused=true` → **`Paused=true`（本次修复的回归点）**；
   - 同一状态 → `UserPaused=true`（暂停原因仍可区分）；
   - 取消 → `Paused=false`（可往返）。

   单实例互斥体已被占用（产品正以托盘形态运行）时**打印 `[SKIP]` 而非判失败**：那是环境限制，不是缺陷。
2. **B 组新增 tooltip 3 项**：把 tooltip 文案规则抽成纯函数 `TrayIconHost.ComposeTooltip(...)`，
   使 `Refresh()` 与自检**共用同一实现**（而不是「在测试里再写一遍」），分别断言：
   未暂停不加后缀 / 仅手动暂停含「（已暂停）」/ 仅锁屏睡眠含「（锁屏/睡眠）」。

**变异测试（证明回归不是空检查）**：把修复**临时回退**成 `scheduler.Paused`、重建、再跑
`--m5-selfcheck` → **恰好 D 组「仅用户手动暂停 → 快照 Paused=true」那一项 FAIL（合计 1 项失败）**；
恢复修复后再次全部通过。→ 该回归项确实咬住了此缺陷，而非恒真。

自检能覆盖「菜单点了会不会回调」「`Snapshot()` 口径对不对」，但**覆盖不到"屏幕上到底显示了什么"**。
§5.9 的修复恰恰是**显示**问题，因此需要一次约 30 秒的实机确认。请按下表逐条看。

**准备**（隔离数据目录，不碰 `%LOCALAPPDATA%\ScreenSpy`）：

```powershell
dotnet run --project ScreenSpy/ScreenSpy.csproj -- --data-dir=artifacts/manual-pause
```

**步骤与观察点**：

| # | 操作 | 应观察到（正确） | 若不对，说明 |
|---|---|---|---|
| 1 | 启动后看主界面 | 状态行显示「**活跃中 —— 正在计入**」（若你不在操作则显示「挂机中（空闲 …s ≥ 阈值 …s）—— 不计入」），页脚说明关闭/退出行为 | — |
| 2 | 右键**托盘图标** → 点「**暂停统计**」 | 菜单项立即变为「**继续统计**」并**带勾**；托盘**图标变灰** | 图标没变化 |
| 3 | 双击托盘（或点「打开主界面」）看状态面板 | 状态行显示「**已暂停（托盘手动暂停）—— 暂停期间的时长不计入**」 | **若显示「挂机中」→ §5.9 缺陷回归了** |
| 4 | 同一面板的会话来 | `暂停=是` | 若为 `暂停=否` → 同上 |
| 5 | **等 20～30 秒**再看「今日」 | 「今日」**停止增长**（数字冻结） | 还在涨 → 暂停没生效 |
| 6 | **鼠标悬停**托盘图标看气泡 | `ScreenSpy · 今日 h:mm:ss（已暂停）` | 没有「（已暂停）」后缀 → 同上 |
| 7 | 再点托盘「**继续统计**」 | 菜单项变回「暂停统计」、勾消失、图标**变回深蓝** | — |
| 8 | 再看主界面「今日」 | 状态行回到「**活跃中 —— 正在计入**」，并恢复**继续增长** | 不增长 → 恢复失败 |
| 9 | 悬停托盘 | 气泡**不再**有「（已暂停）」后缀 | — |
| 10 | 用托盘右键「**退出**」 | 进程结束，通知区域图标消失 | — |

**两种暂停来源的文案必须不同**（这是本次修复刻意保留的区分）：

| 场景 | 状态面板 | 托盘 tooltip |
|---|---|---|
| 仅**手动**暂停 | 已暂停（托盘手动暂停） | ……（已暂停） |
| 仅**锁屏** | 已暂停（锁屏） | ……（锁屏/睡眠） |
| 仅**睡眠/休眠** | 已暂停（睡眠/休眠） | ……（锁屏/睡眠） |
| **手动 + 锁屏/睡眠** | 已暂停（托盘手动暂停 + 锁屏 / 托盘手动暂停 + 睡眠/休眠） | ……（已暂停） |

**若第 3/4/6 条不符**：请把当时的状态面板文字与托盘气泡原文发我 —— 那意味着 §5.9 的缺陷以新的路径复现了。

### 9.1 实测结果（2026-10-06）

按上表 10 条实机走查，**全部符合预期**：

| 关注点 | 观察到的结果 |
|---|---|
| 主界面状态行（手动暂停时） | 显示「**已暂停（托盘手动暂停）—— 暂停期间的时长不计入**」（**未**显示「挂机中」） |
| 会话来「暂停」 | `暂停=是` |
| 暂停期间「今日」 | 数字**冻结**，不计入 |
| 托盘气泡（暂停时） | 带「**（已暂停）**」后缀 |
| 点「继续统计」后 | 状态行回到「活跃中」、数字**恢复增长**、气泡后缀消失 |
| 进程退出 | 托盘「退出」正常结束，通知区域图标消失 |

> 结论：§5.9 的显示口径缺陷**已闭环** —— 代码层（29 项自检 + 变异测试）与屏幕层（本次实机）**两层均通过**。
