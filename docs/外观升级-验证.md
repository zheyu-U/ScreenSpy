## 二、几何：卡片 ≠ 窗口（本次最关键的推论）

外侧投影需要**卡片以外的像素**才画得出来；窗口若仍等于卡片，投影只会在窗口边缘被硬切断。

| 量 | 值 |
|---|---|
| 卡片可视尺寸 | **400 × 400**（M13 之前是 400 × 360） |
| 投影边距（每边） | **20** |
| 分层窗口 / 渲染缓冲 | **440 × 440** |
| 卡片圆角 | **22** |

* 为什么高度从 360 涨到 400：外观升级要"留白更松"，而 360 在"5 行榜单 + 2 行页脚"的最坏情形下
  只剩 6px 底边距（新排放为 196 + 5×32 + 2×18 = 392，底边留白 8px，见 §三）。
* **窗口层行为一行未动**：样式位、命中测试（整窗 `HTTRANSPARENT` / `HTCAPTION`）、z 序自锁、
  "显示桌面"复位、STA 线程模型、`UpdateLayeredWindow` 路径全部照旧 —— 变的是"渲染器往缓冲里画什么"。
* **位置语义的变化（已知并接受）**：窗口左上角 = 卡片可视区左上角 − 20。
  选这个方案是为了**不动任何坐标换算**（浮动拖动、位置上报、两形态共用坐标都不受影响）。
  代价：默认位置 (200,700) 下卡片本体出现在 (220,720)；浮动形态的拖动热区比卡片大一圈。

## 四、实测发现（"只有读像素才能发现"的三件事）

### 4.1 Skia 的**画笔 alpha 会乘到着色器输出上**

`_fill.Color` 的 alpha 不是"被 shader 忽略"的：画轨道时留下的 `alpha = 46`
把进度条填充的强调色 `(118,196,255)` **压成了 `(76,91,107)`**（实测 B 通道 107 ≈ 255×46/255 + 底板的贡献）。

* 症状是"颜色有点脏"，**看上去完全不像 bug** —— 只有把像素读出来才抓得住。
* 处理：`UseShader()` 里**先把自己置为不透明白**再挂 shader；`ClearShader()` 收尾。
* 判据：自检 B3（填充右端位置）+ B3d（右端是轨道而不是强调色）。

### 4.2 影子会铺在**卡片底下**

`CreateDropShadowOnly` 是以卡片形状为源模糊出来的，不加裁剪时它同时画在卡片**下面**。
卡片是半透明的（alpha 222），于是：卡片内部被自己的影子压暗，且越靠边越暗
（实测 alpha 222 → **235** 不等），"底板 alpha 恰好 222"这条设计常量在像素里**再也测不到**。

* 处理：`DrawShadow` 用 `SKClipOperation.Difference` **把卡片本体那一块裁掉**，影子只出现在卡片之外。
* 修好后实测：底板像素 `A=222`，与声明一致（自检 A1/A2/B2b 直接量这个数字）。

### 4.3 取样点会落到**圆角之外**

第一轮自检把 `(25, 417)` 当成"底板"，量到 `A=48`（其实是左下圆角之外的影子）——
失败的**不是渲染器，是判据**。修法：取样点离左右边与底边都 ≥ 30px（大于圆角半径）。

### 4.4 附带修正：PNG 存盘必须做**预乘 → 直通**转换

缓冲是预乘的，而 PNG 解码器按"直通 alpha"解释 —— 直接拷会让半透明处（底板 alpha 222）
比屏幕上**偏暗**，人眼据此评审外观会被误导。`SavePng` 现在做转换（带四舍五入与钳制）。

## 五、自检：`--m13-selfcheck`（50 项）

| 组 | 覆盖 | 项数 |
|---|---|---|
| **A 像素语义** | 预乘（且**能区分**预乘/非预乘）、底板 alpha 精确、四角不是底板、**圆角半径实测**、缓冲写满（哨兵 0）、**投影边距够宽**（窗口最外一圈透明）、可落盘 PNG | 8 |
| **B 外观不变量** | 投影存在/半透明/中性色/向边缘衰减；底板是垂直渐变且两端 alpha 相同；进度条填充宽度=条宽×比例、条带高度锁死、圆头轨道；迷你条；**墨迹锚点**（左对齐、右对齐右缘、墨迹顶边＝实测字面量）；最坏情形不溢出 | 19 |
| **C 接缝与契约** | 工厂单点、有状态渲染器幂等、四项硬失败校验、尺寸必须等于几何推出的尺寸、调试标记是 `Draw` 一等参数、`LayeredSurface` 契约、`Dispose` 幂等 | 12 |
| **D 窗口层回归** | LAYERED / TRANSPARENT+NOACTIVATE / HTTRANSPARENT / 非 topmost / 不在最顶层 / 持续出帧 / **截屏像素上屏判定** / 线程退出与句柄失效 | 11 |

真机实测数据（自检原样输出，摘关键行）：

```
底板像素 (25,220)：B=27 G=20 R=17 A=222；预乘期望 (B=26,G=19,R=17,A=222)；未预乘原色 (B=30,G=22,R=20)
四角 alpha：左上 2 / 右上 2 / 左下 15 / 右下 15（底板 222）
圆角实测：顶边下 2px 处填充起点 x=32（内缩 12px；半径 22 期望约 13）
窗口最外一圈最大 alpha：0（期望 ≤ 2；边距 20px、sigma 6）
投影像素：卡片下缘 +3 → B=0 G=0 R=0 A=64；窗口下缘 -2 → B=0 G=0 R=0 A=0
底板渐变：y=220 → B=27 G=20 R=17 A=222；y=390 → B=20 G=14 R=12 A=222
进度条：条带 y=136..142、x=42..398；填充右端实测 304，期望 ≈ 305（比例 74%）
迷你条：第一行 y=237..241（行首 216）
墨迹实测：标题(13px)={X=43,Y=50,Width=24,Height=10}        声明行位 top=46 left=42
墨迹实测：总时长(34px)={X=121,Y=83,Width=71,Height=28}      声明行位 top=74 left=42
墨迹实测：榜单时间(13px 粗)={X=355,Y=204,Width=43,Height=10} 声明右缘=398
最坏情形：页脚带 y=376..412，其内亮像素 58；卡片底边 2px 内亮像素 0
截屏：onscreen.png；卡片区域 {X=200,Y=700,Width=440,Height=440}；区域内标记像素 576，包围盒={X=210,Y=710,Width=24,Height=24}
```

**几处刻意的写法（值得后人注意）**

* **底板 alpha 是精确相等**（`== 222`），不是"接近"：4.2 的裁剪就是为它服务的。
* **圆角半径是"量"出来的**（卡片顶边下 2px 处填充起点的内缩量），不是读常量 ——
  半径改成 0 会在 A3/A3b 同时失败（见 §六）。
* **墨迹顶边写成零容差字面量**（`TitleInkTop = 50` / `TotalInkTop = 83`）：容差一放开，
  把 `TextTopAdjust` 改成 0（整体上移 1px）就抓不住 —— 实测验证过，见 §六。
* **`B5b2` 是对 `B5b` 的补充**：总时长那一行的差异只有数字（`"今日 "` 是固定前缀，
  两次渲染都会画、相减后消失），所以数字墨迹起点必然在左缘**之后**，不能按 B5b 判。

## 六、变异测试（三轮，每轮恰好命中预期项数）

| 轮次 | 改坏什么 | 期望 | **实测命中** |
|---|---|---|---|
| 1 | `SKAlphaType.Premul` → `Unpremul` | 预乘语义被破坏 | **恰好 2 项**：A1（实测 B=30/G=22/R=19 = 原色）、A1b |
| 2 | 圆角 `Radius` 22 → 0 | 圆角消失 | **恰好 2 项**：A3（四角 alpha 229 ≈ 底板）、A3b（内缩 0px） |
| 3 | `TextTopAdjust` 1 → 0 | 文字整体上移 1px | **恰好 2 项**：B5d（49）、B5e（82） |

每轮改完全部复原，重跑为 50 项全绿。

**第 3 轮直接改了一次判据**：最初 B5d/B5e 写成"墨迹顶边落在行位下方 0..14px 即可"，
把 `TextTopAdjust` 改成 0 时**两条都照过** —— 那等于没有判据。
改成实测字面量后立刻命中。这正是本项目那条纪律的意义：
**改坏关键不变量必须恰好命中预期项数，否则断言是空的。**

## 八、已知取舍（本次**有意**接受的）

1. **位置锚点语义变了**：窗口左上角 ≠ 卡片左上角（差 20px）。换来的是"任何坐标换算都不用改"。

3. **失去"一行回退"**：GDI+ 实现已删除（它做不出渐变底板与柔和投影，无法与新版对照）。
   回退改由 **git** 承担 —— 回到记录 M13 的那个提交即可取回当时的引擎与观感。
4. **卡片占了更多桌面**（+40px 高、四周 +20px 边距）。
5. **动效没做**（淡入/数值滚动/进度条动画）：本次范围是静态观感重设。
