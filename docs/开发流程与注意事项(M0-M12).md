## 一、项目一句话

常驻 Windows 的自用**电脑使用时长追踪器**：统计**真实活跃时长**（剔除挂机 / 锁屏 / 睡眠），**按软件分别统计**，以**半透明卡片贴桌面**展示，并提供**总 / 单软件 / 分类限额**提醒。纯提醒，**不锁屏、不拦截**。

## 三、标准开发循环（每个里程碑都走这 8 步）

> 一句话：**先把事实拿准，再把选择问清，然后"改代码 → 构建 0/0 → 自检 + 变异 → 人工验收 → 同步文档"。**

| # | 步骤 | 目的 | 判据 |
|---|---|---|---|
| 1 | **读准现状** | 规格 + 代码都读，不凭记忆、不凭文档的"技术方案" | 能指出"文档声称 X、代码实际 Y" |
| 2 | **先问方向** | 会**实质改变实现**的取舍，列选项请用户拍板 | 未确认不动手 |
| 3 | **立计划** | 跨多文件 / 多层时先出计划 | 计划条目与验证方式可核对 |
| 4 | **实现** | **纯逻辑优先**；IO / UI 压成薄层 | 口径与几何可确定性断言 |
| 5 | **构建** | 项目约定 **0 错误 0 警告** | `get_errors` 为 0 |
| 6 | **自检 + 全量回归** | 新增回归 + 跑历史全部入口 | **全部 exit 0**；日志 0 处 `[FAIL]` |
| 7 | **变异测试** | **证明回归不是空检查** | 改成错的实现 → **恰好 N 项 FAIL** → 恢复后全绿 |
| 8 | **人工验收 + 同步文档** | 屏幕层自检验不到，只能人眼；文档按惯例同步 | 人工清单逐条通过；相关文档与计数同源 |

**必须人工执行的部分（自检的边界）**：真实拖动 / 鼠标穿透、`SWP_FRAMECHANGED` 是否真的生效、按钮禁用是否真的落到 `IsEnabled`、锁定 / 睡眠真实行为、注销重登录确认自启、托盘菜单交互。**自检只证明"组合根与纯逻辑对"，证明不了"屏幕上真的对"。**

## 四、注意事项

### A. 验证纪律（本项目最关键的一组）

1. **API 全绿 ≠ 像素上屏**。判据必须落到**像素 / 命中测试 / 系统真实状态**，不能只看返回值。M0 的"假阳性"与 M12 的变异 B 都是这条的注脚。
2. **回归必须做变异测试**。写完全绿的断言不算数——把被测逻辑改成错的，看**恰好命中几项**；命中 0 项说明断言是空的。
3. **断言的两种写法不能混**：
   - **行为类**期望值应与**产品输出同源**（如行名、列宽、菜单文案取自产品自身）；
   - **契约类**（键名、协议字段这类对外承诺）必须由测试**独立钉死字面量** —— 与实现共用常量会变成"同义反复"，常量改名时两边一起改，**永远通过**。
4. **每处"写外部状态"的地方，都要有一条绕过被测代码、直接问系统的断言**（M12 变异 B 正是被它抓住的）。
5. **不要用"读源码推断"替代实测**（M0 的判据极性就错在这上面，靠实测才纠回来）。
6. **本机测不出的 bug，靠"换环境会怎样"推演**（`WTSINFOEX` 会话号 = 1 的错位陷阱即由此发现）。
7. **测试装置的错与产品缺陷一样要修干净**，且要注意"等装置"是否等对了对象：等待条件放错用例，会让测试**随机失败**，更危险的是**随机通过**。
8. **断言失败时把实际数值打进断言文本**，很多"看起来像产品缺陷"的问题一眼可辨（如 `SecondsOf=14400s` = 4 × 3600）。
9. **"看起来跑过了"不等于"验证过"**：WinExe 在 PowerShell 里是**异步**返回，必须 `Start-Process -Wait -PassThru` 取真实退出码。

### B. 数据与口径（不变量）

1. **四项守恒**（对账用）：
   ```
   已归因软件 + 不计入使用时长（桌面/外壳/自身） + 无前台·未知 + 锁屏剔除 == 被计入的活跃
   ```
2. **「今日真实活跃」= 本次运行 − 锁屏剔除 + 库中基线**；主界面 / 卡片 / 托盘 / 图表**四处同源**。
3. **展示口径与持久化口径必须同源**：只要"算进去的"和"存下来的"不是同一组，重启 / 跨天 / 降级等边界上就会**安静地对不上**（"重启后今日变小"就是这么来的）。
4. **锁屏 / 睡眠完全不计入**（单列"锁屏剔除"，进等式但**不进展示口径**）。
5. **`app_usage` 只存软件**（归一键），**`daily_activity`** 存非软件两类；**不要**往 `app_usage` 塞伪键。
6. **不读内存榜单**做落库判断（避免跨天丢数据）；存储按**每一拍自身的本地日期**累加。
7. **毫秒攒、整秒落、余数结转**；**增量 upsert**，**提交成功后才扣减**待写。
8. **合并 / 改名必须"数处同源"**：身份层 + 内存榜单 + 待写增量 + 卡片 + 界面。
9. **`limits.target` 用 `NOT NULL DEFAULT ''`**（SQLite 里 NULL 互不相等会让 upsert 退化）。
10. **迁移要可判**：schema 已到 **v3**（v1→v2 加 `daily_activity`；v2→v3 加身份层三表并按用户决定**清空时间历史**）；迁移前后行为差异必须能被自检断言。

### C. Windows 平台陷阱（实测踩过的）

1. **`Progman` 带 `WS_EX_NOREDIRECTIONBITMAP`**，由 DirectComposition 呈现 → **第三方子 HWND 永不上屏**。不要走 `SetParent` 嵌入桌面树。
2. **Win+D 免疫靠 z 序复位**（`HWND_BOTTOM` + `WM_WINDOWPOSCHANGING` 强制 `SWP_NOZORDER` + 显示桌面检测），**不是阻止最小化**；判据 **显示桌面 ⟺ HostZ < ProbeZ**（极性由实测确定）。
3. **`UpdateLayeredWindow` 带 `pptDst` 时每帧都会移动窗口** → 拖动后会被下一秒拽回。正解：`SetWindowPos` 定位一次，每帧 `pptDst = NULL` 只更新内容。
4. **`WS_EX_TRANSPARENT` 改动需带 `SWP_FRAMECHANGED`**，而其**有效性无法在进程内断言**，只能人眼验收。
5. **窗口类名 + `lpfnWndProc`**：类过程是**实例方法指针**，类注册后与那一个实例绑死 → **同名类的第二个实例，消息会走到第一个实例**，静默失效。注册名必须带实例序号。
6. **UWP（26H2）**：应用本体是**独立顶层 `CoreWindow`**，**不是** `ApplicationFrameHost` 的子窗口，且与宿主**无父子 / owner 关系**；只能"子窗口"与"顶层 + 标题配对"两条路径并用，且**候选必须恰好一个**才认。
7. **`WTSINFOEX.SessionId` 不在偏移 0**（有填充）；硬编码偏移会静默读错，会话号 = 1 的机器尤甚。
8. **`default` 结构体的自动属性是 `null`**（构造函数被绕过）→ 对 `default` 实例取 `.Length` 会 NRE；结构体要么显式字段，要么防御式取值。
9. **`ToolStripItem.PerformClick()` 在 `Enabled=false` 时不触发 Click**（已由自检实测确认）。
10. **HKCU Run 键**无需管理员；**删值不删键**；命令行**路径必须加引号**（含空格会被切断）。

### D. 工程与构建环境（本机特有的坑）

1. **`MSB3021/MSB3027`（文件被占用）**：托盘里已有实例在跑 → 先从托盘**退出**再构建。**不要**去结束用户的进程。
2. **不要用自定义输出目录绕开占用**：生成的 `*.g.cs` 会落进工程目录，被默认通配符当成源码编译（曾导致 806 个"成员重复"错误）。需要隔离时只改输出、并确认工程目录干净。
3. **`WinExe` 未连控制台**：直接跑看不到 stdout；看 `artifacts/<里程碑>/*.log`（自检会写 UTF-8 日志）。
4. **自检入口在单实例检查之前**，因此有实例在跑时仍可跑自检；但**占用单实例互斥体的那几组会 `[SKIP]`**（按设计跳过，不是失败）。
5. **`docs/*.md` 有若干份 VS 打不开**（报"无效的 URI / 无法打开文本文档"）。此时改用"**载荷文件 + 纯 ASCII 脚本**（`ReadAllText`/`WriteAllText`）"，并**保持各自原有行尾与 BOM**，且**每处替换都要求恰好命中 1 次**。
6. **`artifacts/` 被 `.gitignore` 忽略，但其中不少是文档引用的证据**（`m0-spike/`、`product-demo/`、`*-card*.png`、`m3-rawlog/`、`diag-uwp/`、各里程碑日志）→ **不能整体删除**；只清"随用随生"的隔离库（`manual-*`）。
7. **`.gitattributes` 的 `* text=auto` + 本机 `core.autocrlf=true`** 会产生 `LF will be replaced by CRLF` 提示，提交时归一化为 LF，**属正常现象**。
8. **构建产物 `bin/obj` 可再生**，但用户在运行时不要删。

### E. 文档与协作

1. **会实质改变实现的选择先列选项请用户确认**；开放需求**先讨论再做**；拿不准**直接问，不揣摩**。
2. **每完成一项就更新文档**：规范（`开发文档.md`）、里程碑验证、决策日志（D 编号）、阶段总结、计数与索引（`1005.md` / `README.md` / `.slnx`）。
3. **保留原文、追加"后续修正"标注**，不改写历史记录（证据链优先）。例：M0 阶段"临时演示入口（M5 完成后删除）"这类表述，**原文保留**并另加修正说明。
4. **清理时要区分"证据"与"草稿"**：被文档引用的产物保留，随用随生的隔离数据可删。
5. **操作失误按实告知用户，但不写入项目结论文档**（结论文档只记产品事实）。
6. **不要把已删/已过时的内容留在"当前状态"描述里**：过期的**展示代码**比过期的注释更危险——注释误导读者，展示代码会在界面上"说谎"，且不报错。

## 六、自检与变异测试速查

### 自检入口（退出码 0 = 全部通过）

```powershell
$exe = "ScreenSpy\bin\Debug\net10.0-windows\ScreenSpy.exe"

& $exe --m1-selfcheck  --logic-only   # 计时调度器 + 空闲检测
& $exe --m2-selfcheck  --logic-only   # 锁屏/睡眠（--lock-test / --sleep-test 会真锁屏/真睡眠）
& $exe --m3-selfcheck  --logic-only   # 前台识别 + 分类 + 守恒
& $exe --m4-selfcheck  --logic-only   # 存储 + flush + 续算（含 schema 版本与表清单）
& $exe --m5-selfcheck                 # 托盘图标与菜单
& $exe --m6-selfcheck                 # 卡片渲染与数据映射
& $exe --m7-selfcheck                 # 卡片双形态 + 位置持久化 + 入口互斥
& $exe --m9-selfcheck                 # 身份层 / 自定义名称 / 限额引擎
& $exe --m10-selfcheck                # 近 7 天图表
& $exe --m11-selfcheck                # UWP 应用名修正
& $exe --m12-selfcheck                # 开机自启（真实 HKCU 临时键往返）

& $exe --demo-card                    # 卡片嵌入形态 + 截屏像素判定（M0 结论的可复现验证）
& $exe --diag-uwp                     # 打印真实 UWP 窗口关系（排查 UWP 识别）
```

- 日志同时写入 `artifacts/<里程碑>/`（UTF-8）。
- **有实例在运行**时，占用单实例互斥体的少数几组会 `[SKIP]`（正常）。
- 全量回归必须**逐个等待**取真实退出码：`Start-Process -Wait -PassThru`。

### 变异测试配方（每次补完回归都要做）

1. 选一条**关键不变量**（守恒、去重、续算、合并、契约键名……）；
2. 把它**临时改成错的**（改到"行为真的变了"，不只是改报告）；
3. 重新构建，跑对应自检；
4. **必须恰好命中 N 项 FAIL**，且**FAIL 全部落在预期的那一组**；命中 0 项 = 断言是空的，要重写；
5. **恢复**改动，重新构建，确认全绿；
6. **把命中项数与症状写进对应的 `M*-验证.md`**。

## 九、协作偏好（沿用）

- 用**中文**回复；详细解释技术细节；

- 保留原文 + 追加"后续修正"标注，不改写历史。
