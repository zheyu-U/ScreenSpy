## 一、结论摘要

1. **卡片已由 SkiaSharp 渲染，外观与 GDI+ 基线一致**：自检 **44 项全部通过**（退出码 0），
   构建 **0 错误 0 警告**。
2. **几何部分是逐字节等价的**（不是"看起来差不多"）：
   - 底板/圆角/描边：无内容区域差异 **0 像素**；
   - 进度条**填充区**：最大通道差 **0**；
   - 调试标记矩形：与 GDI+ **逐字节相同**（差异 0 像素）。
3. **差异只出现在字形光栅化上**，且已逐条量化归因（见 §四）。
4. **真的上屏**：`--demo-card --win-d` 实测，Win+D 后标记色块命中 **576 像素、包围盒 {X=210,Y=710,24×24}** ——
   正是卡片 (200,700) + 标记偏移 (10,10) 的精确位置与尺寸（M0 的判据）。
5. **回退是一行**：`CardRendererFactory.Create` 里把 `SkiaCardRenderer` 换成 `GdiCardRenderer`。
   ⚠ **已失效**（外观升级时 GDI+ 实现被移除，回退改由 git 承担，见文首说明）。

## 二、改了什么（接口面）

### 2.1 接缝：从"给你一块画布"改成"给我一块像素缓冲"

```csharp
internal interface ICardRenderer : IDisposable
{
    // bits = 自顶向下 32bpp 预乘 BGRA；stride = width * 4
    void Draw(IntPtr bits, int width, int height, int stride, CardModel model, Rectangle? debugMarker);
}
```

**为什么必须这么改**：M13 之前 `LayeredSurface` 对外交出的是 `Graphics`（GDI+ 画布），
等于把"用哪块内存、什么像素格式"的决定权给了渲染器 —— 两个引擎**无法产出同一种东西**，
也就谈不上逐像素对照。改成传 `bits` 后，接缝本身钉死了输出格式，于是可以直接 diff。

`debugMarker` 进参数（而不是留在 `CardWindow` 里用 GDI+ 画）：它是 M0 像素判定的**唯一锚点**，
必须跨引擎存在，否则换引擎后"卡片有没有真的上屏"就再也无法客观判定。

### 2.2 选择点唯一

`CardRendererFactory.Create` 是"默认用哪个引擎"的**唯一答案**；刻意**不做**运行时自动回退
（Skia 失败就悄悄换 GDI）—— 那属于被否决的路径 (c) 的同类问题（静默掩盖风险）。

⚠ 外观升级后：`GdiCardRenderer` 已删除，"换回一行"这个回退手段不存在了；
**接口与选择点仍然保留**，理由变成"让窗口层不认识具体引擎"（M15 拆工程的前提）。

## 三、自检：`--m13-selfcheck`（44 项）

| 组 | 覆盖 | 项数 |
|---|---|---|
| **A 像素语义取证（spike）** | 半透明底板出来的**是预乘**字节；断言**能区分**预乘/非预乘（否则是空断言）；alpha 未被色彩管理改动；圆角外全 0 透明；调用方缓冲被完整写入（哨兵残留 0）；输出可落盘 PNG | 6 |
| **B 与 GDI+ 基线对照** | 标记矩形逐字节相同、底板颜色一致、圆角外透明；**三种字号的真实墨迹包围盒**（左对齐/右对齐/大字）；整体差异与差异分布 | 15 |
| **C 接缝与契约** | 工厂默认产出 Skia、渲染器有状态但幂等、入参校验四种硬失败、尺寸不符拒绝、标记由参数驱动（传 null 即无）、`LayeredSurface` 缓冲契约自洽、`Dispose` 幂等 | 12 |
| **D 窗口层回归** | 真实卡片：LAYERED / TRANSPARENT+NOACTIVATE / HTTRANSPARENT / 非 topmost / 不在最顶层 / 持续出帧 / **截屏像素上屏判定** / 线程退出与句柄失效 | 11 |

真实数据（自检原样输出）：

```
底板像素 (5,180)：B=20 G=16 R=14 A=205          ← 预乘正确
标记像素：B=170 G=0 R=255 A=255；与 GDI 差异 0 像素
墨迹对照 12.5px（标题）  ：Skia={X=19,Y=18,W=23,H=10}  GDI={X=21,Y=19,W=23,H=10}
墨迹对照 32px （总时长）：Skia={X=90,Y=47,W=66,H=26}  GDI={X=94,Y=46,W=67,H=25}
墨迹对照 13px （排行榜）：Skia={X=339,Y=130,W=43,H=10} GDI={X=335,Y=130,W=42,H=11}
整体差异：精确 17521（12.17%）；显著（通道差>2）11347；文字墨迹合计 17742 像素
左侧空白带（x<14，无任何内容）差异：0 像素
进度条带：填充区(x=18..286) 最大通道差 0；尾部(x≥288) 最大通道差 1
```

**关于"整体差异 12.17%"**：这个数字几乎全部来自字形光栅化（两个引擎的光栅化器不同，
字形边缘逐像素不同是必然的）。所以 B6 的判据**不是**一个拍脑袋的百分比，而是拿
"文字墨迹面积"当尺子：`显著差异 ≤ 1.5 × 文字墨迹像素数`（11347 ≤ 26613）。
结构错位会立刻冲破这个界（对照 §五 变异测试的 95.82%）。

## 四、实测发现（文档没写全的部分）

### 4.1 GDI+ 与 Skia 的**行框上沿**差 0~2px，且随字号变化

| 字号 | Skia 墨迹顶 | GDI 墨迹顶 | 差 |
|---|---|---|---|
| 12.5px（标题） | 17 | 19 | 2 |
| 32px（总时长） | 46 | 46 | 0 |
| 13px（排行榜） | 129 | 130 | 1 |

**原因**：GDI+ 的行高来自 GDI 的**整数**字体度量（`tmAscent` 向上取整），Skia 用浮点度量，
两者相差不到 1px，但落到**像素取整**上就变成 0~2px 不等的差 —— 因此**不可能用一个公式算出来**。

**处理**：统一补偿 `TextTopAdjust = +1px`（补偿后为 1 / 1 / 0，三个字号全部落进 ±1 容差）。
刻意**不给每个字号各配一个魔数**去贴合某一个具体字符串 —— 那只是在拟合测试数据。

### 4.2 GDI+ 的 `MeasureString` 含 padding，Skia 更紧

- **起笔横向差**：标题 Skia=19 / GDI=21（差 2）；大字 Skia=90 / GDI=94（差 4）；
  排行榜 Skia=339 / GDI=335（差 4，因右对齐由宽度反推）。
- **右对齐右缘**：Skia=382（恰好 = `w - pad`）/ GDI=377（差 5）。

也就是说：**Skia 把文字放在"布局意图"的位置上，GDI+ 因为 padding 把它推偏了几像素**。
按 §5.7 的预判（"字形边缘允许小幅差异"），这类 ≤6px 的平移判为可接受，
自检用 `MaxInkWidthDelta = 6` 盯着，"再大就不是度量差而是布局错了"。

### 4.3 两处**合成**差异（都在纯图形区域）

| 现象 | 数字 | 原因 |
|---|---|---|
| 进度条**未填充尾部** | 每行 95 列（≈364×(1−0.74)），最大通道差 **1** | "半透明白(alpha 64) 叠在半透明底板(alpha 205)"的 source-over **舍入**差 1 个 8bit 单位 |
| 进度条**填充右边界**那一列（x=287） | 最大通道差 **63** | GDI+ 把填充宽度**截断成整数**（`(int)(364×0.74)=269`），Skia 用浮点（269.36） |

第二处"更精确"的其实是 **Skia**；GDI+ 的整数截断才是异类。所以判据写成两条各有含义的检查
（填充区必须逐字节相同；尾部只允许 ±1），而**不是**一个笼统容差 —— 后者只会逼着人调阈值把问题盖住。

### 4.4 全屏扫描标记色会**误命中**（一条假阳性判据）

第三轮变异测试时 D8 报了"卡片确实上屏"，但包围盒是 `{X=542,Y=282,45×46}` ——
离卡片 (200,700) 十万八千里，且比 24×24 的标记还大。说明全屏 `Analyze` 会命中别处的粉紫色像素。

**处理**：`ScreenCapture.Analyze` 新增可选 `region`，D8 改为**在卡片自己的矩形内**统计。
这条判据原本会给出假阳性，现在不会。

## 五、变异测试（三轮）

| 轮次 | 改坏什么 | 期望 | **实测命中** |
