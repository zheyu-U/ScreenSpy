# M0 桌面嵌入验证结论

> 目的：判定 **Windows 11 26H2** 上“**嵌入桌面壁纸层 + 逐像素半透明**”是否成立（《开发文档》§7.1 / §8 的 M0，P0 生死判定点）。
> 验证工具：临时项目 `Spike/ScreenSpy.Spike.csproj`（非产品代码，**已于 2026-10-05 删除**；证据图移至 `artifacts/m0-spike/`）。
> 相关文档：《开发文档》§5.8 / §5.9 / §7.1 / §7.2 / §7.4；《对话纪要》§8.3。

> ⚠️ **本文档中的路线 A 结论已被后续实验推翻，请以 `docs/M0-B+验证.md` 为准（2026-10-05）。**
> 路线 A 在 26H2 上"记账层全绿但屏幕上一个像素都没有"——嵌进桌面树的子窗口不会上屏（已被像素级实验排除渲染/重父化/遮挡三种解释）。
> 最终结论：**不嵌入，采用路线 B+（顶层分层窗口 + z 序自锁 + 显示桌面检测复位）**，并已通过截屏像素判定的客观验证（含 Win+D 免疫）。

## 2. ⚠️ 与《开发文档》§5.8 的实测差异（需修订文档）

**《开发文档》§5.8 的描述（经典三步）：**
> ① 向 `Progman` 发送 `0x052C`；② 枚举**顶层**窗口，找到那个**不包含 `SHELLDLL_DefView` 子窗口的顶层 `WorkerW`**（即壁纸层）；③ `SetParent`。

**实测（build 26300.9457）的实际结构：**

| 时刻 | `Progman` 的子窗口 |
|------|-------------------|
| 注入 `0x052C` **前** | `SHELLDLL_DefView`(0x10108)、`SysListView32`(0x1010C)、`SysHeader32`(0x10114) |
| 注入 `0x052C` **后** | 上述三个 **+ 全屏可见的 `WorkerW`(0x1503A0, 1920×1200)** |

也就是说：

- 26H2 上 **`SHELLDLL_DefView`（图标层）直接是 `Progman` 的子窗口**；
- **壁纸层是 `Progman` 的全屏子 `WorkerW`**，而**不是**经典的“顶层同级 `WorkerW`”；
- 本机上**不存在**“顶层、无 `SHELLDLL_DefView` 的 `WorkerW`”（顶层那 16 个 `WorkerW` 尺寸均为 170×47 且不可见，属其它进程所有，**若不加校验会误选**）。

**建议修订 §5.8**：把“经典三步”改写为**自适应定位**（本 Spike 的 `DesktopEmbed.FindEmbedTarget()` 已实现）：

1. 若 `SHELLDLL_DefView` 宿主即 `Progman`（新版桌面）→ 取 **`Progman` 的全屏可见子 `WorkerW`**；
2. 否则（经典结构）→ 取“`SHELLDLL_DefView` 宿主之后、**可见且覆盖全屏**的顶层 `WorkerW`”（加尺寸/可见性校验，避免误选无关 `WorkerW`）；
3. 兜底 → 直接嵌入 `Progman`，并用 `SetWindowPos(hwnd, hDefView, …)` 把组件压到图标层之下。

## 5. 路线 A 自动检测结果（`--route=A`）

```text
窗口创建            : 成功
嵌入尝试(SetParent) : 是
嵌入成功            : 是
窗口可见            : 是
目标宿主            : 0x1503A0（WorkerW）

关键事实：
· 分层窗口创建成功：hwnd=0x1508D0，尺寸 400×360
· 扩展样式=0x080800A0（WS_EX_LAYERED=True、WS_EX_TRANSPARENT=True、WS_EX_NOACTIVATE=True）
· 已存在可用的壁纸层 WorkerW，跳过 0x052C 注入
· 嵌入目标类型：Progman 的子 WorkerW（26H2 新版桌面壁纸层）
· SetParent 前 GetAncestor(GA_PARENT)=0x1000C（顶层窗口）
· SetParent(hwnd → 0x1503A0) 返回值=0x1000C，GetLastError=0
· SetParent 后 GetAncestor(GA_PARENT)=0x1503A0 → 与目标一致 ✅
· SetParent 后 GetAncestor(GA_ROOT)=0x10100（类=Progman）
· 窗口样式 0x84000000 → 0x54000000（移除 WS_POPUP，加入 WS_CHILD|WS_VISIBLE|WS_CLIPSIBLINGS）
· 改为 WS_CHILD 后 GetParent=0x1503A0，GetAncestor(GA_ROOT)=0x10100
· 窗口屏幕坐标=(80,80)-(480,440)
· 嵌入后 IsWindowVisible=True；宿主客户区=(0,0)-(1920,1200)
```

**踩坑记录（对实现很重要）：**

- 不能用 `GetParent` 判断嵌入是否成功。对**仍带 `WS_POPUP`** 的窗口，`GetParent` 返回的是 **owner（此时为 NULL）**，
  会误判为“失败”。正确做法是用 **`GetAncestor(hwnd, GA_PARENT)`**（判定直接父窗口）与
  **`GetAncestor(hwnd, GA_ROOT)`**（判定是否已归入 `Progman` 树）。
- `SetParent` **不会**自动把 `WS_POPUP` 改成 `WS_CHILD`（微软文档明示，为了兼容性）。
  嵌入后应显式 `SetWindowLong(GWL_STYLE)` 完成样式切换，否则行为不可预期。
- 注入 `0x052C` 会**新增**一个壁纸层 `WorkerW`。实现时应**先查找、只有找不到才注入**，避免反复注入堆积多余 `WorkerW`。

## 8. 路线 B（伪嵌入降级方案）现状

- 顶层分层窗口（`WS_EX_LAYERED|TRANSPARENT|NOACTIVATE|TOOLWINDOW`）压到 `HWND_BOTTOM`，
  每 2 秒重新压低；逐像素 alpha 渲染同样正常（连续提交多帧无异常）。
- 已知局限（实测前即预期）：**会被其它窗口遮挡**，且位于图标层**之上**（靠鼠标穿透保证图标可点）。
- 结论（已修订）：**B 是正确方向，但不完整**——它已满足“贴桌面 + 被窗口覆盖 + 半透明 + 鼠标穿透”，
  唯一缺口是 `Win+D` 会把卡片藏掉。**该缺口已由路线 B+ 补上并通过客观验证**（见 `docs/M0-B+验证.md`）：
  B+ = B + z 序自锁（`WM_WINDOWPOSCHANGING` 强制 `SWP_NOZORDER`）+ “显示桌面”检测与 z 序复位（移植 Rainmeter）。
  路线 A 已实测证伪，不再作为前置条件。
