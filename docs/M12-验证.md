## 4. 关键设计

### 4.1 注册表是唯一事实来源

界面**不记状态**，每次问注册表：

```
UpdateAutoStartControls()  →  QueryAutoStart()  →  AutoStartRegistration.Query()  →  Registry.GetValue
                          ←  AutoStartState{Enabled, Command, Error}
```

于是三种情况自动对上，无需额外代码：

- **写失败**（权限 / 策略）→ 开关立刻弹回真实值 + 提示写出原因；
- **用户在别处改过**（任务管理器启动项 / 注册表编辑器）→ 1 秒内反映到界面；
- **存在同名条目但指向别的路径** → 显示"未启用"，并说明那条残留会被覆盖（`PointsElsewhere`）。

### 4.2 三条同时成立才算"已启用"

```
已启用  ⟺  值能解析出路径  ∧  带 --autorun  ∧  路径 == 本进程的 exe
```

第二条**不能省**：只比路径的话，界面会说"已启用开机自启"，而登录时其实会**弹出一个主界面窗口**（不是承诺的形态）—— 又一次"界面在骗人"。

### 4.3 自启的窗口策略（含一条降级例外）

```csharp
ShouldShowMainWindow(autoRun, trayAvailable) => !autoRun || !trayAvailable;
```

- 自启 + 托盘可用 → **不显示主界面**（只进托盘）；
- 自启 + **托盘不可用 → 必须显示** —— 那时没有任何入口能呼出界面，不显示就等于"看不见也关不掉"（M5b 那条降级契约在自启场景下的延续）。

### 4.4 写操作**一律回读**

`Enable()` / `Disable()` 不假设写入成功：写完（或失败后）都调 `Query()`，把**真实状态**返回给上层。
理由：写入"看起来成功"但被重定向 / 被策略拦掉时，回读是唯一的判据。

### 4.5 线程与权限

- 只碰 **HKCU**（当前用户），**不需要管理员权限**，也不影响其他用户；
- 界面在 UI 线程每秒读一次注册表（一次键值读取，开销可忽略）；
- **删除只删值，绝不删键**：真实的 Run 键是 Windows 自己的，删掉会影响其它自启项。
  `TryRemoveTestKey` 因此带两道守卫（拒绝生产 Run 键路径 + 只接受自检专用前缀）。

| **A 纯逻辑** | 29 | 构造（含空格加引号 / 已带引号不双引号 / 空白裁剪）；解析（带引号 / 不带引号 / 无参数 / 半个引号 / null / 空白 / 大小写 / 参数顺序）；匹配（本程序 / **缺 --autorun 不算已启用** / 指向别处 / 大小写 / 非字符串 / null）；路径比较（大小写 / 结尾反斜杠 / 非法路径不抛 / 空值）；窗口策略三条；**契约字面量**三条 |
| **B 注册表真实往返** | 18 | 在 **HKCU 临时键**上做 写 → 读 → 改 → 删：初始未启用；启用后**直接读原始值核对**；幂等；**裸路径（缺 --autorun）判未启用**；值被写成 DWORD 也不抛；关闭后值为 null；重复关闭不报错；**守卫拒绝删真实 Run 键**；清理后无残留 |
| **C 组合根与接线** | 12 | `--autorun` 解析（含大小写）且**不落进"未知参数"**；真实 `ProductRuntime` 带 `--autorun` 照常启动且**无 autorun 相关警告**；提示文案四态各说各话（已启用 / 未启用 / 同名残留 / 注册表不可用） |

**为什么 B 组要写真实注册表**：mock 只能验证"我以为的注册表语义"，验证不了真实的读写权限、键值类型与回读时序。

**为什么契约用字面量**：`Software\Microsoft\Windows\CurrentVersion\Run` 与值名 `ScreenSpy` 是"与用户机器上已存在的注册表内容"之间的兼容契约；拿常量自比自会变成同义反复（M7 变异测试的教训）。

| 轮 | 变异 | 结果 |

| A | `PointsToThisApp` 只比路径、不再要求 `--autorun` | ✅ **恰好 3 项 FAIL**（A 的"只比路径不算数" + B 的两条"关键"） |

**变异 B 的第一次尝试失败了，值得记一笔**：我只把 `return` 改成伪造的"成功"，**真正的 `SetValue` 还在**，于是所有断言照旧通过 —— 这是**变异太弱**，不是断言无效。
去掉写入语句后才被抓住。教训：**变异要改到"行为真的变了"，而不是只改"报告的内容"**。

## 7. 已知局限（如实声明）

1. **无法在自检里验证"重启电脑后真的自动启动"**：那需要真实重启。自检验证到的是"注册表里确实有指向本程序且带 `--autorun` 的条目 + 命令行能被正确解析 + 该组合根能正常启动"。**最终验收需要你重启一次**（或注销再登录）。
2. **自启时"不显示主界面"这条无法在自检里断言**：它取决于 `App.OnStartup` 里的 `window.Show()` 分支（纯函数 `ShouldShowMainWindow` 已断言，但"WPF 窗口真的没显示"验不了）。需要你实际登录一次看托盘。
3. **注册表被组策略锁定时**：`Query()` 会返回 `Error`，界面禁用开关并显示原因 —— 这条路径**只在代码层保证**，未在真实受限环境验证。
4. **多用户**：只写当前用户的 HKCU。切到另一个 Windows 账户时不会自启（符合预期，但请知悉）。
5. **不是"计划任务"**：注册表 Run 键**无法延迟启动、无法提权**。若将来需要"登录后延迟 1 分钟启动"或管理员权限，要改走计划任务 —— 那时界面文案与自检都要跟着改。
6. **开发期路径会被写进注册表**：在 `bin\Debug` 下点开开关，写进去的就是那个临时路径；换到正式安装目录后需要**重新勾一次**（界面会把真实命令行显示出来，便于发现）。
7. **`--autorun` 只影响窗口显示**，不影响任何统计口径；但它**不是安全边界**（任何人都能手动带这个参数启动）。

## 10. 结论

1. **M0–M12 全部里程碑完成** —— 项目从"桌面嵌入生死判定"走到了最后一个功能项。
2. **自启的形态是用户承诺的那种**："登录时只进托盘"，且**只有同时满足"指向本程序 + 带 --autorun"才算已启用**，界面不会承诺一个不会发生的行为。
3. **状态只有一个来源**（注册表），且每次回读 —— 不会出现"界面说已启用、实际没有"这类本项目最忌的静默不一致。
4. **一条降级契约被延续**：托盘不可用时自启也**必须**显示窗口，否则用户会失去唯一的入口。
5. 59 项自检 + 两轮变异测试（命中 3 / 1）+ 10 项回归全绿；"重启后自动出现"这一条需要**你重启一次**做最终验收（§8 第 9 条）。
