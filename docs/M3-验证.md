## 2. 关键设计决策

### 2.1 分类优先按窗口类名，辅以进程名黑名单

`explorer.exe` **不能**按进程名一律过滤：它既是桌面（类名 `Progman` / `WorkerW` / `SysListView32`），
也可能是前台的文件资源管理器窗口（类名 `CabinetWClass`）——后者是**真实应用**，必须计入。
因此：

| 判据 | 内容 |
|---|---|
| 类名 → 桌面 | `Progman` / `WorkerW` / `SHELLDLL_DefView` / `SysListView32` / `FolderView` |
| 类名 → 外壳 | `Shell_TrayWnd` / `Shell_SecondaryTrayWnd` / `NotifyIconOverflowWindow` / `TaskListThumbnailWnd` / `Windows.UI.Core.CoreWindow` |
| 进程名 → 外壳 | `StartMenuExperienceHost` / `SearchHost` / `SearchApp` / `ShellExperienceHost` / `TextInputHost` / `LockApp` / `dwm` / `csrss` |
| 类名或进程名 → 锁屏 | 类 `LogonUI` / `LockScreenFrameWindow`；进程 `LogonUI` / `Winlogon` / `LockApp` |

判定次序：**自身（pid 比较）→ 锁屏 → 桌面 → 外壳 → UWP 宿主 → 应用**。
自身优先，避免自己的卡片把自己算成“使用中”。

### 2.2 “取不到就不猜”

`GetForegroundWindow` 返回 NULL → `None`；拿到窗口但取不到进程名（进程已退出 / 权限受限）
→ `Unknown`。二者都**不计入任何软件**，但**分别计数**，便于日后判断“漏了多少”。
**绝不**按窗口标题或类名硬凑一个软件名——那会污染统计且难以察觉。

### 2.3 同名合并：按进程名，不带 pid、不用标题

- **不用窗口标题**：浏览器每个页面标题都不同，会把一个软件拆成成百上千条；
- **不带 pid**：Chrome / Edge 会开很多子进程，前台通常只有一个，必须合并。
- 合并键 = 进程名小写（忽略大小写）。

### 2.4 UWP 宿主**先计入**，精确名留到 M11

`ApplicationFrameHost` 归为 `UwpHost`，**仍按应用计入**（展示名“UWP 应用（待修正）”）并单独计数。
理由：§5.5 的修正属 M11；在此之前若直接过滤，UWP 应用的时长会被**整段丢掉**——少计比暂不精确更糟。

### 2.5 不加进程名缓存

心跳只有 1 Hz，`Process.GetProcessById(pid).ProcessName` 的开销可忽略；
而缓存会引入“**pid 复用导致张冠李戴**”（把时长记到错误的软件头上）的风险，
与本项目“宁可少计、不可错计”的取向相悖。

### 2.6 时间守恒（本里程碑最重要的不变量）

```
已归因(AttributedTotal) + 不计入使用时长(FilteredTotal) + 无前台/未知(UnattributedTotal)
  + 锁屏剔除(LockScreenExcludedTotal) == 调度器的“今日活跃”
```

四者互斥且覆盖全部**被计入**的拍，因此等式必须**毫秒级精确成立**。
它一次性覆盖“漏记 / 重复记 / 单位错”三类问题，是 M3 的核心断言（自检与真实观察都验它）。

> 🔄 **口径统一（2026-10-06）**：原先“锁屏”被算进 `已过滤`（即**计入活跃**），
> 现按口径改为**完全不计入**并单列 `锁屏剔除`；`已过滤` 收窄为“桌面 / 外壳 / 自身”，
> 展示名改为 **「不计入使用时长」**；`未归因` 展示名改为 **「无前台 / 未知」**。
> 另：`IsFiltered` 也随之**不含锁屏**（新增 `IsLockScreen`）。
> 之所以把锁屏单独留一项而不是直接丢掉：丢掉会让等式少一项、**无法再用等式发现漏记**。
> 自检新增 2 项专门断言“锁屏进剔除桶、不进三个展示桶”“四项闭合”。

### 2.7 不修改 M1/M2

`AppUsageBridge` 只**旁听** `Ticked` 事件，不侵入调度器；
只有当 `ActivityTick.IsActive` 为真时才把 `tick.Elapsed` 记到当时的软件头上，
因此挂机 / 锁屏暂停 / 时间空洞期间**天然不计入**。
跨天顺序由调度器保证（**先** `DayRolled`、**后** `Ticked`），先清空、再记当拍。

## 4. 已知局限（如实声明）

1. **§5.4 的原始验收方式**是“逐个切换几个软件各停留 **1 分钟**，误差在几秒内”。
   自动化只能替代到“观察窗口内切换并核对汇总”，**长时间人工对照仍建议由你做一次**
   （命令见 §6）；不过“归一秒 = 墙钟一秒”这件事已由**端到端守恒检查**（§3.1 末组）客观保证。
2. **UWP 应用**目前一律记为「UWP 应用（待修正）」，真实名修正属 §5.5 / M11。
3. **权限受限进程**（部分系统进程）取不到进程名 → 记入“未知”且不计入；这类时长会进 `未归因`，不会记错。
4. 应用名映射表（`FriendlyNames`）目前是**小规模内置表**，未映射的退回进程名本身（不会漏统计）；
   后续可从文件版本信息（`FileDescription`）取更友好的名字。
5. **无独立测试工程**（按 D12 决策），上述确定性检查以**内嵌**方式覆盖，不构成回归保护网。
6. 本机 15 秒真实观察里**只出现过一个软件**（Visual Studio），
   因此“多软件切换”这一场景由 A 段的脚本化检查覆盖，真实多软件已在卡片演示中部分体现（桌面被过滤）。
