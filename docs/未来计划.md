# 未来计划（M13–M17：UI 重写与内存优化）

> 背景与理由见 `UI-重写思路.md`；接口面清单见 `核心接口说明.md`。
> **本文只管"做什么、按什么顺序、怎么算做完"。**

---

## 一、总览

```
M13 卡片渲染换 SkiaSharp ──────────┐
                                   ├─→ M16 主界面重写（用户主导）
M14 契约抽取 + --mem-probe ─→ M15 UI 进程化（拆工程）─┘
```

| 期 | 内容 | 依赖 | 可并行 |
|---|---|---|---|
| **M13** | 卡片渲染引擎换 SkiaSharp（像素等价） | 无 | 与 M14 |
| **M14** | 契约抽取（`IScreenSpyCore` + 表现层）与 `--mem-probe` | 无 | 与 M13 |
| **M15** | UI 进程化：`Contracts` / `Core` / `UI` 三工程 | M14 | — |
| **M16** | 主界面重写（框架内现代化，或换框架） | M14（必须）、M15（建议） | — |
| **M17** | 框架评估 spike（可选） | M15 | — |

### 两条不可动摇的顺序约束

1. **M14 必须早于 M16**：自检直接引用 `MainWindow` 的静态成员不先解耦就重写 UI =
   把验证网一起删掉（详见 `UI-重写思路.md` 第三节）。
2. **M15 必须先于"换框架"**：XAML 框架加载**不可卸载**，只有进程边界才能把内存完整还给 OS。

## 二、M13：卡片渲染换 SkiaSharp

> **状态：✅ 已完成（2026-10-08，见 `docs/M13-验证.md`）** ——
> 卡片已由 SkiaSharp 渲染，**几何部分与 GDI+ 基线逐字节等价**（无内容区域 0 差异、
> 进度条填充区 0 差异、标记矩形逐字节相同），差异只出现在字形光栅化上且已逐条量化归因。
> `SkiaSharp` 钉死 **2.88.9**。回退原为「把 `CardRendererFactory` 里的一行换回 `GdiCardRenderer`」；
> ⚠ **外观升级时该实现已移除**（它做不出渐变底板与柔和投影），回退改由 git 承担。
> 本轮**只做像素等价迁移**（D85）。**外观升级已于 2026-10-08 独立完成**
> （投影 / 渐变底板 / 圆角 / 排版；同时移除 GDI+ 基线与跨引擎对照，见 `docs/外观升级-验证.md`）；
> **动效**（淡入 / 数值滚动 / 进度条动画）仍未做。

### 目标
用 SkiaSharp 替换 GDI+ 渲染卡片，**外观保持不变**（像素等价迁移），为后续质感升级（圆角/投影/渐变/微动效）打底。

### 范围（做）
1. **5 分钟 spike 取证**（先行，见下）；
2. 引入 `ICardRenderer` 接缝（**不暴露画布，暴露"给我一块像素缓冲"**）：
   ```csharp
   internal interface ICardRenderer
   {
       // bits = 自顶向下 32bpp 预乘 BGRA；stride = width*4
       void Draw(IntPtr bits, int width, int height, int stride, CardModel m, Rectangle? debugMarker);
   }
   ```
3. `GdiCardRenderer`：现有 `CardRenderer` **原样搬入**（作回归基线）—— ⚠ **已在外观升级时移除**；
4. `SkiaCardRenderer`：**路径 (b)** —— `SKBitmap` + `SKCanvas` 画，再 `MemoryCopy` 进 DIB；
5. `LayeredSurface` 瘦身：保留 DIB + `Present`，不再持有 GDI+ 对象；
6. **保留调试标记色块**（M0 像素判定的唯一锚点，必须作为 `Draw` 参数存在）；
7. 逐项重调布局常量（字体度量变了）。

### 不做
- 不改窗口层（`CardWindow` / `NativeWindowHost` / `DesktopZOrderManager`）；
- 不改 `CardModel` / `CardData` 契约；
- **不改外观**（外观升级留到本次迁移稳定之后，独立一步做）；
- 不做 (a) 直写 DIB / (c) 双路径（见 `UI-重写思路.md` §5.4–5.5）。

### Spike（先做，5 分钟）
| 验证 | 判据 |
|---|---|
| `new SKCanvas(SKBitmap)` 画出的像素正确 | 读回像素核对 BGRA + 预乘值（50% 白 → `128,255,255,255`） |
| `colorSpace: null` 时半透明不被改色 | 同上 |
| 截屏真的上屏 | **复用 M0 的不透明标记色块**做精确锚点 |
| 离线可 diff | Skia 输出可编码 PNG 落盘 |

### DoD（完成判据）
- 构建 0 错误 0 警告；
- `--m13-selfcheck`（新增）：渲染器选择、像素格式、标记色块位置、布局关键锚点；
- **像素等价验收**：与 GDI+ 渲染器做 PNG diff（结构/颜色/位置一致，字形边缘允许小幅差异）；
- **变异测试**：至少一条回归能被定向改坏后抓住；
- 卡片人工验收（鼠标穿透 / 被窗口盖住 / Win+D 不最小化——这些**是窗口层行为，不应变化**）。

### 风险与回退
| 风险 | 对策 |
|---|---|
| 字体度量导致错位 | 预期内；逐项重调 + PNG diff；GDI+ 基线可随时对照 |
| SkiaSharp 版本 API 漂移 | **钉死版本**（2.88 系最稳；3.x 文本 API 不同） |
| 字体回退链变化（中文掉字） | 原样保留 `Microsoft YaHei UI → Microsoft YaHei → Segoe UI → Tahoma` |
| 回退方案 | `ICardRenderer` 切回 `GdiCardRenderer`（一行） |

## 三、M14：契约抽取 + 内存判据

### 目标
把"UI 框架"与"表现逻辑"解耦，让验证网不再依赖 `MainWindow`；同时给内存立客观判据。

### 范围（做）
1. **`IScreenSpyCore` 显式化**（草案见 `核心接口说明.md` 第四节）：
   - `ProductRuntime` 实现它；
   - `App` 注入的 6 个委托（`IsAdjusting` / `ToggleAdjust` / `IsFloating` / `ToggleCardMode` / `QueryAutoStart` / `SetAutoStart`）+ 卡片可见性，**收进接口**；
   - **`out` 参数改成结果类型**（跨进程前置，趁还在同进程时改，自检能兜住）。
2. **表现层搬到不引用 UI 框架的命名空间**（如 `Presentation/`）：
   - 文案合成：`ComposeNonAppTopRow` / `DescribeState` / `DescribeSession` / `ComposeChartHint` / `BuildAutoStartHint` / `BuildPositionHint`；
   - 契约与下拉项：`IdentityChoice` / `BuildChartDimensionChoices` / `ChartTotalLabel` / `ComposePositionControlAvailability` / `ComposeChartScope`；
   - 规则：**这一层只允许 `string` / 数字 / `IReadOnlyList` / 自家 DTO；禁止 `Thickness` / `Brush` / `StackPanel` / `Visibility`**。
3. **自检改锚点**：从 `MainWindow.*` 改为 `Presentation.*`（**改一行 using 就该能跑**）。
4. **`--mem-probe`**：在四个时刻打印 `WorkingSet64` / `PrivateMemorySize64` / `GC.GetTotalMemory(false)` / 线程数 / 句柄数：
   1. 核心启动完成（托盘 + 卡片就绪）
   2. 静置 60 秒后（稳态 + 泄漏）
   3. 主界面显示后
   4. **主界面关闭后**（进程化的验收点）
   结果落 JSON 到 `artifacts/`。
5. **主窗口惰性创建**（首次显示时才 `new MainWindow(...)`）——这一刀**不依赖任何框架决策**。

### 不做
- **不拆工程**（物理拆分留到 M15）；
- 不改任何业务口径。

### DoD
- 构建 0/0；`get_errors` 0/0；
- **自检零引用 `MainWindow`**（可用 grep 客观核对）；
- 全部既有自检仍全绿（M1–M12）；
- `--mem-probe` 四组数据入档，作为后续基线；
- **变异测试**：至少验证"自检确实在测新锚点"（把表现层某条规则改坏 → 对应断言 FAIL）。

### 风险
| 风险 | 对策 |
|---|---|
| 搬迁中漏改消费点 | 逐项 grep 引用；自检 + 变异测试兜住 |
| `out` → 结果类型改动面大 | 逐处改、逐处加断言；同进程阶段改动可控 |
| 表现层"偷偷引用 WPF 类型" | 用 grep 断言（`Thickness\|Brush\|Visibility`）+ 代码审查 |

## 四、M15：UI 进程化（拆工程）

### 目标
让**静默时完全不加载 UI 框架**；主界面关闭时内存完整归还 OS。

### 范围（做）
1. **物理拆工程**：
   - `ScreenSpy.Contracts`（DTO + `IScreenSpyCore` + 协议消息）
   - `ScreenSpy.Core`（采集 / 口径 / 存储 / 限额 / 托盘 / 卡片）—— **禁止引用 WPF**
   - `ScreenSpy.UI`（主界面 + 对话框）
2. **核心去掉 WPF**：
   - 入口不再派生自 `Application`；**自建消息泵**（隐藏窗口 + `GetMessage/DispatchMessage`，或 WinForms `Application.Run()`）；
   - `App.OnStartup` 里的 **WPF `MessageBox.Show` 换成**托盘气泡 / WinForms MessageBox / TaskDialog；
   - **12 个自检入口搬到"核心引导"**。
3. **IPC**：命名管道 + 行分隔 JSON（带 `version`）；`PipeCoreClient : IScreenSpyCore`。
4. **生命周期与失败模式**（清单见 `UI-重写思路.md` §6.5）：
   核心未运行 / UI 崩溃 / 核心断开 / 版本不匹配，四种都必须有明确行为。
5. **假核心**（供 UI 开发）：一个返回固定数据的 `IScreenSpyCore` 实现，
   让 UI 可以在**没有核心**的情况下开发。

### 不做
- 不改主界面的**内容**（那是 M16）；
- 不改卡片窗口层。

### DoD
- 构建 0/0；
- **静默进程不含 WPF/WinUI 程序集**（可客观核对：进程模块列表）；
- `--mem-probe` 的第 4 个时刻（UI 关闭后）**内存回落** —— 这是进程化的核心验收点；
- 托盘菜单、卡片、限额提醒在**核心单独运行**时全部正常；
- UI 侧代码**只改装配，不改业务逻辑**；
- 失败模式逐条演示（含"核心未运行"提示）。

### 风险
| 风险 | 对策 |
|---|---|
| 托盘图标"显示但点不动"（消息泵没建） | 先做消息泵，再搬托盘；自检断言菜单可点 |
| 自检入口搬迁遗漏 | 逐个入口跑一遍，退出码为 0 |
| 单实例语义混乱 | 明确：互斥体归核心；UI 只保证"只有一个主窗口" |
| IPC 版本不匹配 | 协议带版本；不匹配时**明确报错**，不试图兼容 |

## 五、M16：主界面重写（用户主导）

### 目标
把"十来个区块堆成一条长滚动"改成**有信息架构的界面**；外观现代化。

### 前置条件
- **M14 已完成**（验证网已解耦）；
- 建议 M15 已完成（框架选择自由）。

### 建议的工作方式（绞杀者模式）
1. 引入**导航骨架**（侧栏/分页）：运行状态 / 软件与分类 / 限额 / 趋势 / 设置；
2. **一页一页搬**，每搬一页：`run_build` 0/0 → 自检全绿 → **人眼验收** → 文档同步；
3. MVVM + 主题库（WPF 内现代化）或换框架。

### 必须提前接受的边界
> **本项目的自检验不了屏幕。** 它验的是模型、几何、Win32 状态与纯函数文案；
> **"好不好看、是否错位、动效是否顺滑"只能靠人眼**。
> UI 重写会让"人工验收"比例显著上升 —— 这是必须接受的成本，别指望自检兜住外观。

### 重写时请遵守
- 数据入口只用 `IScreenSpyCore`（见 `核心接口说明.md`）；
- "每秒全量重建"改成**增量更新**（稳定键 + 差异），避免绑定风暴；
- **不要**再引入"手动抑制标志"（`_identityUiBusy` / `_chartUiBusy` 这类）——用绑定取代；
- 对话框统一成一种服务（别各写一套）。

## 六、M17（可选）：框架评估 spike

**触发条件**（满足任意一条才做，否则留在 WPF）：

1. 需要 **WPF 确实做不到的能力**（真正的 GPU 复合动效、跨平台）；
2. 主界面要变成**长期打开、频繁交互**的应用；
3. 要把**卡片渲染与主界面统一到同一套绘制引擎**（→ Avalonia + Skia）；
4. 能接受**自检宿主、部署方式、托盘/互操作胶水**都要重做一遍。

**做法**：沿用 M0 的作风 —— **先取证、再决策**：做一个最小 spike，
把候选框架的"空窗口基线内存 / 启动耗时 / 与托盘和自绘窗口的互操作可行性"量出来，写成报告再定。
