## 3. 关键设计

### 3.1 三层分离：口径 / 几何 / 绘制

```
库(app_usage + daily_activity)
   → ChartQuery（IO + 降级）
   → ChartBuilder（口径：谁能算、算多少）      ← 纯逻辑，可确定性断言
   → BarChartLayout（几何：柱高多少像素）      ← 纯逻辑，可确定性断言
   → BarChartView（摆控件）                    ← 唯一碰 UI 的一层
```

**为什么这样切**：用户已说明以后要重做 UI。若把"多少秒算多高"写在控件代码里，重做 UI 时那套算法会被重写一遍，
于是"图看起来对、数字悄悄变了"这类问题会重新出现。现在换 UI 只需替换 `BarChartView`，
口径（81 项断言里的大部分）原样保留。

### 3.2 口径（与既有三处同源）

| 维度 | 值 |
|------|-----|
| 每天总量 | 该日 `app_usage` 之和 **+** 该日 `daily_activity`（不计入使用时长 + 无前台/未知） |
| 某个软件 | 该日该**归一键**的秒数 —— **不含**非软件那部分（它不属于任何软件） |
| 某个分类 | 该日该分类下各软件之和（分类来自身份层，未分类返回空串） |

* **锁屏/睡眠**按既有口径**完全不计入**：它本来就不落库（不写 `daily_activity`），因此这里天然不含，不需要额外减法。
* **窗口固定右端是"今天"**：7 天 = 今天 + 前 6 天（含首尾）。左端随今天滚动，
  不会出现"今天有数据但不在图里"这种只有跨天才暴露的偏差。

### 3.3 「无记录」与「0」刻意分开

`ChartBar.HasData` 只看"那天在库里有没有行"：

| 情况 | 显示 |
|------|------|
| 那天程序没运行过（库里没有任何行） | **空槽** + 数值 `—` |
| 那天运行过，但这个软件没用过 | **不画柱** + 数值 `0:00` |
| 那天运行过且有该软件 | 柱 + `h:mm` |

"那天没开机"与"那天开了一天但从没用过这个软件"是两件事，不该长得一样。

### 3.4 身份层**现取**（不缓存）

`ChartQuery` 的显示名 / 分类解析是**委托**（`key => AppNamingRules.EffectiveName(_identity, key)` 等），
每次读图时现取。因为用户可能在运行期改名、改分类、合并软件 ——
若在构造时缓存一份，改名之后图表标题就会永远停在旧名（**不报错的错**）。
自检 D 组专门验证这条：改完名**立刻**读图，标题必须是新名，且旧名（含友好名）不再出现。

### 3.5 刷新节奏：**每 15 秒**读一次库

图只读库，而库本身最多 15 秒才更新一次（flush 间隔），所以读得更勤只是重复读同一份数据。
于是刷新节奏与落库间隔对齐；另外在"进入窗口 / 改维度 / 改目标 / 点刷新 / 身份层变动"时立即读一次。

**两个下拉框不跟着每秒刷新重建**（只重建图表本身）—— 重建下拉框会把用户正打开的列表销毁掉，
表现为"点了没反应"，与「软件与分类」一节是同一条教训。

### 3.6 降级：**明确报错，而不是给一张空图**

存储不可用时返回一句可显示的原因（"存储不可用，因此看不到历史数据……"）。
空图会被读成"这几天真的没用电脑"——那是另一种"界面在骗人"。

### 4.5 过程中我自己的三处断言写错（如实记录）

`--m10-selfcheck` 第一次跑出 3 项 FAIL，**全部是我的断言写错，产品行为是对的**：

1. 用 `ChartModel.Empty`（0 根柱）去断言"提示里说没有历史记录"——但那个分支针对的是"有窗口、但 7 天全空"，改用真实的 7 天空模型；
2. 断言软件维度标题含进程名 `devenv`——实际用的是**友好名** `Visual Studio`（产品更对），改为断言友好名；
3. 断言分类维度今天 = 1300 ——把非软件那 300 秒也算了进去，而分类维度**本来就不该含非软件**，正确值是 1000。
   顺带把这条升级成一对更强的断言：**总量 1300 ≠ 分类 1000**（口径互不污染）。

> 这三条的价值在于：它们说明这组断言**真的在跑**，而不是照着实现抄一遍。

## 5. 已知局限

1. **今天那根最多滞后约 15 秒**：这是"只读库"决策的必然结果（用户已选），界面已明说。
   若日后想让它与上方大字永远相等，需要改成"今天用内存口径、前 6 天读库"——那是**口径变更**，不是缺陷修复。
2. **图表不可被自检覆盖到像素**：`BarChartView` 摆控件的效果（柱是否真的画出来、颜色、对齐）只能靠人眼；
   自检覆盖的是它**输入**（`ChartModel`）与**几何**（`BarChartLayout`）。这也是把逻辑与绘制分开的另一动机。
3. **无缩放 / 无悬停详情**：只做了"柱 + 日期 + 数值"与逐柱提示（ToolTip）。坐标轴刻度、图例、点击下钻都未做。
4. **历史数据受 M9-1 迁移影响**：M9-1 的 schema v2→v3 按决策**清空了时间历史**，
   因此刚升级完时只有今天有数据，前 6 天是空槽（这是 D57 的既定后果，不是本里程碑的缺陷）。
5. **软件候选来自"近 7 天的库"**：某软件若 7 天内一次都没出现，就不在候选里（要给它看趋势须先让它出现一次）；
   这与"图只读库"保持一致，避免"下拉里能选、选了却是空图"。
6. **分类维度不含"未分类"这一档**：未分类是"没设"，不是一种分类，因此不作为可选目标。
